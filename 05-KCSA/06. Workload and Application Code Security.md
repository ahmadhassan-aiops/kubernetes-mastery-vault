# 06. Workload and Application Code Security

## What Are Workloads?

In Kubernetes, a **workload** is an application or service running in the cluster, managed through objects such as Pods, Deployments, StatefulSets, DaemonSets and Jobs.

Securing a workload means securing two things:

1. the **application code** that runs inside the containers
2. the **configuration** that controls how those containers run

## How to Secure Workloads and Code

### 1. Write secure code

- Follow secure coding practices to avoid common vulnerabilities: **SQL injection**, **cross-site scripting (XSS)** and **cross-site request forgery (CSRF)**. The **OWASP Top 10** is the standard reference list.
- Review code regularly to catch security issues early.

### 2. Use trusted base images

- Use minimal, official base images from trusted registries.
- **Benefit:** fewer packages mean fewer vulnerabilities and a smaller attack surface.

### 3. Scan code and images

- **Tools:** SonarQube or Semgrep for code; Trivy or Grype for images and dependencies.
- **Integration:** run them in the CI/CD pipeline on every commit and every image build.

### 4. Manage secrets properly

- Store passwords, tokens and keys in **Kubernetes Secrets**, never in images, code or ConfigMaps.
- **Encrypt Secrets at rest** in etcd, or keep them in an external manager such as **HashiCorp Vault** or a cloud secrets manager. See [topic 11](11.%20Authentication%2C%20Authorization%20and%20Secrets.md).

### 5. Restrict traffic with Network Policies

- Allow only the communication each workload needs.
- **Benefit:** fewer attack paths, and a compromised pod can't reach everything.

### 6. Enforce pod security

- Use **Pod Security Admission** (the replacement for PodSecurityPolicy) and **security contexts** to prevent running as root, privilege escalation and extra capabilities.
- **Benefit:** least privilege at the pod level. Hands-on in [CKS topic 15](../04-CKS/15.%20Security%20Contexts%20for%20Least%20Privilege.md).

### 7. Monitor and log continuously

- **Monitoring:** Prometheus and Grafana for health and behaviour.
- **Logging:** Fluentd or Fluent Bit shipping to Elasticsearch, Loki or a cloud service.
- **Alerting:** notify on suspicious activity or deviations from normal patterns.

### 8. Patch regularly

- Keep a schedule for updating both the application and the platform under it.
- Automate checks: **kube-bench** checks the cluster against the CIS Benchmark; **kube-hunter** probes it for weaknesses from an attacker's point of view; image scanners find outdated components.

## A Secure Workload Example

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: api
  namespace: prod
spec:
  replicas: 2
  selector:
    matchLabels:
      app: api
  template:
    metadata:
      labels:
        app: api
    spec:
      serviceAccountName: api                # dedicated account
      automountServiceAccountToken: false    # no API token unless needed
      securityContext:
        runAsNonRoot: true
        seccompProfile:
          type: RuntimeDefault
      containers:
      - name: api
        image: registry.example.com/api@sha256:<digest>   # pinned by digest
        securityContext:
          allowPrivilegeEscalation: false
          readOnlyRootFilesystem: true
          capabilities:
            drop: ["ALL"]
        resources:
          requests: { cpu: 100m, memory: 128Mi }
          limits:   { cpu: 500m, memory: 256Mi }
        envFrom:
        - secretRef:
            name: api-credentials          # secrets from a Secret, not the image
```
