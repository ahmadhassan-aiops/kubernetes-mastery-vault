# 02. Cloud Provider and Infrastructure Security

Cloud security is a **shared responsibility**: the provider (AWS, Azure, GCP and others) secures the cloud itself, and you secure what you put in it.

```text
          ┌───────────────────────────────────────────────┐
Customer  │ Data · Identities and access · Applications   │  "security IN the cloud"
          │ OS and network configuration · Encryption     │
          ├───────────────────────────────────────────────┤
Provider  │ Physical data centers · Hardware · Network    │  "security OF the cloud"
          │ infrastructure · Virtualization layer         │
          └───────────────────────────────────────────────┘
```

For managed Kubernetes (EKS, AKS, GKE), the provider also runs and patches the **control plane**; you remain responsible for workloads, RBAC, node configuration (unless nodes are fully managed) and network policies.

## The Provider's Responsibilities

### 1. Physical data centers

- Physical access control to the buildings and hardware
- Surveillance cameras and security staff
- Environmental controls: fire suppression, power and climate

### 2. Network infrastructure

- **DDoS protection** against traffic floods
- **IDS/IPS** (intrusion detection and prevention systems) to catch attacks
- **Encrypted transmission** inside the provider's network

### 3. Compliance and certifications

Providers are audited against global standards (ISO 27001, SOC 2, PCI DSS and others) to prove they meet strict security requirements.

## Your Responsibilities

### 1. Access management

- Control who can access your cloud resources with **IAM** policies.
- Use strong passwords and **multi-factor authentication (MFA)**.
- Grant **least privilege** and review access regularly (see [CKS topic 12](../04-CKS/12.%20Minimizing%20IAM%20Roles%20and%20External%20Network%20Access.md)).

### 2. Data encryption

- Encrypt data **at rest** (stored) and **in transit** (moving across the network).
- Manage keys with a key management service such as **AWS KMS** or **Azure Key Vault**.

### 3. Network configuration

- Design the **VPC** (virtual private cloud) carefully: private subnets for nodes and databases.
- Use **security groups** and firewall rules to allow only the traffic you need, and block everything else.
- Keep the Kubernetes API endpoint private, or restrict it to known IP ranges.

## Infrastructure Hardening for Kubernetes Nodes

- Use minimal, hardened OS images and patch them regularly.
- Protect the **instance metadata service** (require IMDSv2, block it from pods).
- Encrypt node disks.
- Restrict SSH and use a bastion host.
- Benchmark nodes against the CIS guidelines.

Reference: https://kubernetes.io/docs/concepts/security/overview/#cloud
