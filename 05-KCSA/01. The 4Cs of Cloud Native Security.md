# 01. The 4Cs of Cloud Native Security

Cloud native security is built in **layers**, like an onion. Each layer protects the ones inside it, and a weak outer layer undermines everything within. The four layers are known as the **4Cs**:

```text
┌──────────────────────────────────────────┐
│ Cloud      (outermost)                   │
│  ┌────────────────────────────────────┐  │
│  │ Cluster                            │  │
│  │  ┌──────────────────────────────┐  │  │
│  │  │ Container                    │  │  │
│  │  │  ┌────────────────────────┐  │  │  │
│  │  │  │ Code   (innermost)     │  │  │  │
│  │  │  └────────────────────────┘  │  │  │
│  │  └──────────────────────────────┘  │  │
│  └────────────────────────────────────┘  │
└──────────────────────────────────────────┘
```

| Layer | What it is | Main owners |
|---|---|---|
| **Code** | The application itself | Developers |
| **Container** | The packaged image and its runtime settings | Developers and security teams |
| **Cluster** | Kubernetes: the control plane, nodes and workloads | Kubernetes administrators (CKA) and security engineers (CKS) |
| **Cloud** | The infrastructure everything runs on: data centers, VMs, networks | Cloud administrators, plus the cloud provider |

---

## 1. Code: the Core of the Application

Code is the set of instructions that tells your software what to do.

- **Code quality** is about how well written and efficient the code is.
- **Code security** is about making sure the code can't be misused or attacked.

A **code vulnerability** is a flaw an attacker can exploit, for example to take over the application and steal or delete data.

### Finding vulnerabilities

**Security code analysis** examines code for weaknesses, automatically with tools or manually through code review. The main tool families:

| Tool type | How it works |
|---|---|
| **SAST** (Static Application Security Testing) | Analyses the source code **without running it** |
| **DAST** (Dynamic Application Security Testing) | Tests the **running** application from the outside |
| **IAST** (Interactive Application Security Testing) | Combines both, with an agent inside the running app |
| **SCA** (Software Composition Analysis) | Scans **third-party libraries** for known vulnerabilities |

### Securing code

- Run SAST, DAST, IAST and SCA tools regularly, ideally in the CI pipeline.
- Follow secure coding practices, such as **validating user input** to prevent SQL injection and cross-site scripting (XSS).
- Expose only the ports the application really needs.
- Use TLS for all communication.
- Fix issues as soon as scans find them.

## 2. Container: the Packaged Application

A container is like a sealed box holding the code and everything it needs to run, so it behaves the same everywhere.

Container security means:

- the **image** contains no known vulnerabilities or unnecessary software
- the container **runs** with the least privilege possible

### Securing containers

- **Scan images**, including the operating system packages inside them, while building.
- Use **minimal, trusted base images**.
- **Run as a non-root user** with only the access it needs (least privilege).
- Use strong identity and access controls on registries and build systems.

More in [topic 05](05.%20Artifact%20Repository%20and%20Image%20Security.md).

## 3. Cluster: the Management Layer

A cluster is a group of machines (nodes) that run containers and manage how they work together. Kubernetes is the cluster layer.

Cluster security protects the components that control the applications and their resources:

- **RBAC** controls who can do what in the cluster.
- **Regular updates** patch Kubernetes and its components.
- **Network Policies**, **Pod Security Admission** and **Secrets encryption** protect workloads.

Most of this folder, and the whole [CKS folder](../04-CKS/README.md), is about this layer.

## 4. Cloud: the Infrastructure Layer

The cloud (AWS, Azure, GCP or your own data center) is where everything runs: physical machines, virtual machines and networks.

Cloud security protects the infrastructure and its communication channels:

- Isolate virtual machines and networks from each other.
- Secure cloud APIs with strong authentication.
- Encrypt data in transit and at rest.

Responsibility here is **shared** between you and the provider ([topic 02](02.%20Cloud%20Provider%20and%20Infrastructure%20Security.md)).

---

## Key Takeaway

You can't fully secure an inner layer if an outer one is weak: perfect code in a container running as root, on a cluster with open RBAC, in a cloud account without MFA, is still exposed. Apply controls at **every** layer.

Reference: https://kubernetes.io/docs/concepts/security/overview/
