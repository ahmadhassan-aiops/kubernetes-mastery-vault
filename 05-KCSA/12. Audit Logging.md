# 12. Audit Logging

**Audit logging** records every request made to the Kubernetes API server: who made it, what they did, to which resource, when, from where, and whether it succeeded. Like a kingdom's official records, it lets you reconstruct what happened.

## Why It Matters

- **Security investigations:** a history of every API action to find the root cause of an incident and spot suspicious activity.
- **Compliance:** many regulations require logging of user activity; audit logs are the evidence.
- **Troubleshooting:** find who changed a configuration and when.

## What Gets Recorded

- API requests and their responses, from users, controllers and applications
- the authenticated identity and groups, and the authorization decision
- changes to cluster resources: Deployments, Pods, Namespaces, RBAC and more

## Stages

Each request can produce an event at several stages:

| Stage | When |
|---|---|
| `RequestReceived` | As soon as the request arrives |
| `ResponseStarted` | Response headers sent (long-running requests such as `watch`) |
| `ResponseComplete` | Response body completed |
| `Panic` | The server failed while handling the request |

## Levels

| Level | Records |
|---|---|
| `None` | Nothing |
| `Metadata` | User, verb, resource, timestamp, response code; **no bodies** |
| `Request` | Metadata plus the request body |
| `RequestResponse` | Metadata plus request and response bodies |

> Log **Secrets** at `Metadata` only. At `Request` or `RequestResponse`, the secret values themselves would end up in the log.

## The Audit Policy

Rules are checked **in order**; the **first match** decides the level.

```yaml
# /etc/kubernetes/audit-policy.yaml
apiVersion: audit.k8s.io/v1
kind: Policy
omitStages:
- RequestReceived                     # halves the volume
rules:
# Don't log noisy read-only system traffic
- level: None
  users: ["system:kube-proxy"]
  verbs: ["watch"]
# Secrets, ConfigMaps and tokens: metadata only, never the content
- level: Metadata
  resources:
  - group: ""
    resources: ["secrets", "configmaps", "serviceaccounts/token"]
# Full detail for changes to workloads and RBAC
- level: RequestResponse
  verbs: ["create", "update", "patch", "delete"]
  resources:
  - group: ""
    resources: ["pods"]
  - group: "apps"
    resources: ["deployments"]
  - group: "rbac.authorization.k8s.io"
# Everything else: metadata
- level: Metadata
```

## Enabling It on the API Server

Add the flags to `/etc/kubernetes/manifests/kube-apiserver.yaml`:

```yaml
- --audit-policy-file=/etc/kubernetes/audit-policy.yaml
- --audit-log-path=/var/log/kubernetes/audit/audit.log
- --audit-log-maxage=30        # days to keep old files
- --audit-log-maxbackup=10     # number of old files to keep
- --audit-log-maxsize=100      # MB before rotating
```

The API server runs in a container, so the policy file and log directory must also be **mounted** into the static pod:

```yaml
volumeMounts:
- mountPath: /etc/kubernetes/audit-policy.yaml
  name: audit-policy
  readOnly: true
- mountPath: /var/log/kubernetes/audit/
  name: audit-log
volumes:
- name: audit-policy
  hostPath:
    path: /etc/kubernetes/audit-policy.yaml
    type: File
- name: audit-log
  hostPath:
    path: /var/log/kubernetes/audit/
    type: DirectoryOrCreate
```

Save the file; the kubelet restarts the API server automatically.

## Verify

```bash
kubectl run audit-log-test --image nginx
sudo tail -n 5 /var/log/kubernetes/audit/audit.log | jq '{user: .user.username, verb, resource: .objectRef.resource, name: .objectRef.name, code: .responseStatus.code}'
```

Each line is a JSON event, for example a `create` on `pods` named `audit-log-test` by `kubernetes-admin` with response code `201`.

## Backends

| Backend | How |
|---|---|
| **Log** | JSON lines written to a file (above) |
| **Webhook** | Events sent to an external HTTP API (`--audit-webhook-config-file`) |

## Best Practices

- **Enable it** on every cluster; managed services have a setting for it.
- **Choose levels carefully:** enough detail to investigate, without drowning in volume or logging secret values.
- **Centralize** logs off the control-plane nodes (Fluent Bit, a SIEM, a cloud log service) so attackers can't erase them.
- **Set a retention policy** that meets your compliance needs.
- **Analyse and alert:** watch for `exec` into pods, reads of Secrets, RBAC changes, `403` spikes and requests from unexpected IPs.
- Combine with **runtime detection** (Falco), which sees what happens *inside* containers, where the audit log can't.
