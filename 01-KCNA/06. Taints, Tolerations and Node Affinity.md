# 06. Taints, Tolerations and Node Affinity

These features control **which pods may run on which nodes**.

## Taints and Tolerations

| | Taints | Tolerations |
|---|---|---|
| **What** | A note you put on a **node** saying "handle with care" or "special node" | A pod's **preference** about taints on nodes |
| **Purpose** | Mark nodes to influence pod scheduling | Let a pod accept (tolerate) a node with a specific taint |
| **Effect** | Only pods with a matching toleration can be scheduled there | The pod can run on nodes carrying that taint |

**Analogy:** a taint is a "Spicy!" label on a snack. A toleration is a pod saying "I'm fine with spicy," so it can still eat that snack.

> **Taints are set on nodes. Tolerations are set on pods.**

Note that a toleration only **allows** a pod onto a tainted node. It does not force the pod there. To attract pods to specific nodes, use node affinity.

## Node Affinity

**Definition:** node affinity lets you state a **preference or requirement** for scheduling pods onto particular nodes, based on node characteristics (labels) or constraints.

**Two types:**

| Type | Strength | Behaviour |
|---|---|---|
| `requiredDuringSchedulingIgnoredDuringExecution` | **Hard** requirement | The pod is scheduled **only** on nodes that match the rules. |
| `preferredDuringSchedulingIgnoredDuringExecution` | **Soft** requirement | The pod **prefers** matching nodes, but can run elsewhere if none are available. |

`IgnoredDuringExecution` means that if a node's labels change after the pod is running, the pod is not evicted.
