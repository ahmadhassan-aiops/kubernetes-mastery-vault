# 07. DaemonSets and Static Pods

## DaemonSets

**Simple definition:** a DaemonSet makes sure a specific pod runs on **every node** in the cluster.

**Why we need it:** some tools must run on each machine, for example:

- a **monitoring agent** collecting CPU and RAM data from every node
- a **log collector** shipping logs to a central system
- a **network tool** managing traffic on every node

Instead of placing the tool on each node by hand, you tell Kubernetes: *"Make sure this runs on all nodes, always."*

**How it behaves** (with Node1, Node2 and Node3):

- Create a DaemonSet for a logging agent, and Kubernetes starts **one pod per node**.
- Add Node4, and the pod is added there automatically.
- Remove a node, and its pod is removed too.

You never manage these pods yourself; Kubernetes does it.

**In one line:** a DaemonSet is a robot helper that puts a tool on every machine and keeps it running there.

## Static Pods

**Simple definition:** static pods are created **directly by the kubelet on a node**, not by the control plane (scheduler or controller manager).

### Use case 1: control plane components

When you install Kubernetes with `kubeadm`, core services such as `kube-apiserver`, `kube-scheduler` and `kube-controller-manager` run as **static pods** on the master node. The control plane isn't up yet, so the scheduler can't place them; the kubelet starts them instead.

### Use case 2: node-specific applications

Run something on **one specific node only**, such as a custom monitoring tool on a powerful node, a security scanner on a node with sensitive access, or a local file-processing job.

### How they work

1. Put a pod YAML file in the kubelet's manifest folder, usually `/etc/kubernetes/manifests/`.
2. The kubelet watches the folder and starts any pod described there.
3. Delete the file and the pod is deleted. Update the file and the pod restarts with the new config.

> Static pods do **not** appear in `kubectl get deploy` or `kubectl get rs`, because the control plane doesn't manage them. You see them with `kubectl get pods --all-namespaces`.

### Advantages

| Feature | Benefit |
|---|---|
| Simple | Drop a file in a folder to run a pod, no `kubectl apply` needed |
| Works without a full control plane | Used to run the control plane itself |
| Node-local | Runs only on the node that has the file |
| Self-healing | If it crashes, the kubelet restarts it |

## Static Pod vs DaemonSet

| Feature | Static pod | DaemonSet |
|---|---|---|
| Managed by | kubelet on the node | Kubernetes control plane |
| Runs on all nodes? | No, only on the node with the YAML | Yes, on all (or selected) nodes |
| Created by | YAML file in a folder | YAML sent with `kubectl apply` |
| Needs the control plane? | No | Yes |

**Analogy:** static pods are a lunch box you bring from home and keep in your own locker. The school cafeteria (control plane) didn't give it to you, so you can eat even before the cafeteria opens.
