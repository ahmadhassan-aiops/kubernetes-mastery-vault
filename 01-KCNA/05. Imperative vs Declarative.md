# 05. Imperative vs Declarative

## The Idea

- **Imperative:** you give step-by-step orders. *"Hey robot, create 3 toy blocks, colour them red, green and blue, and stack them."*
- **Declarative:** you describe the end result. *"Here is a picture of how I want it to look. Make it look like this."*

In Kubernetes, imperative means running `kubectl` commands that act right away, while declarative means writing the desired state in a YAML file and letting Kubernetes make it so.

## Side by Side

| Scenario | Imperative | Declarative |
|---|---|---|
| Create a deployment | `kubectl create deployment my-deployment --image=my-app` | Write a YAML file with the deployment details, then `kubectl apply -f my-deployment.yaml` |
| Scale a deployment | `kubectl scale deployment my-deployment --replicas=5` | Change `replicas` to 5 in the YAML, then `kubectl apply -f my-deployment.yaml` |
| Change a container's image | `kubectl set image deployment/my-deployment my-container=my-new-image` | Update the image in the YAML, then `kubectl apply -f my-deployment.yaml` |
| Delete a resource | `kubectl delete deployment my-deployment` | `kubectl delete -f my-deployment.yaml` |

**Rule of thumb:** imperative is quick for one-off tasks and exams; declarative YAML is better for real projects because the file can live in Git and be reviewed and reapplied.
