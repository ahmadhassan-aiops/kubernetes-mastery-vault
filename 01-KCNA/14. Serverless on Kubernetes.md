# 14. Serverless on Kubernetes

## What Is Serverless in Kubernetes?

Serverless means **running code without managing the infrastructure**. You write functions or services, and the platform handles scaling, scheduling and resource provisioning.

On Kubernetes, serverless is provided by frameworks such as:

- **Knative** (the most popular)
- **OpenFaaS**
- **Kubeless**

These tools hide pods, services and scaling logic. Your code **runs only when needed**; Kubernetes allocates resources, scales the app and cleans up when it's idle (it can even scale to zero).

## Serverless vs Traditional Servers

| Aspect | Traditional servers | Serverless |
|---|---|---|
| Server management | Manual provisioning, configuration and maintenance | No servers to manage; the platform does it |
| Scalability | Manual scaling, possible downtime or delays | Automatic, on-demand scaling |
| Cost model | Pay for servers whether used or not | Pay only while code runs |
| Responsibility | You handle security, patching and upkeep | Shared with the provider; you focus on app logic |
| Complexity | Needs infrastructure expertise | Simpler through abstraction |
| Flexibility | Full control over the stack | Focus on code; infrastructure is abstracted |
| Deployment time | Slow setup and configuration | Fast deployment, quicker time to market |
| Usage-based billing | No | Yes |
| Best for | Stable, predictable workloads | Event-driven, real-time or occasional tasks |
