# 11. DNS in Kubernetes

## What Is DNS in Kubernetes?

DNS is the cluster's **phone book**. Instead of remembering pod or service IPs, you reach them by **name**, and Kubernetes translates the name into an IP automatically, for example `my-service.default.svc.cluster.local`.

## Why It Matters

Without DNS you would have to track IP addresses that change every time a pod restarts or moves, and communication between apps would keep breaking. DNS gives you:

- **Stable names**
- **Automatic updates** when IPs change
- Resolution **inside the cluster only**, unless you expose a service explicitly

## How It Works

Kubernetes runs a DNS add-on, usually **CoreDNS**, inside the cluster. When a pod connects to a service by name (such as `mysql` or `backend-service`):

1. The pod sends a DNS query.
2. CoreDNS answers with the service's **ClusterIP**.
3. The pod connects to that IP.

## Example

```yaml
metadata:
  name: my-service
  namespace: default
```

Other pods can reach this service as any of:

```
my-service
my-service.default
my-service.default.svc.cluster.local
```

## Naming Structure

```
<service-name>.<namespace>.svc.cluster.local
```

| Part | Meaning |
|---|---|
| `my-service` | Service name |
| `default` | Namespace |
| `svc` | It is a service |
| `cluster.local` | Default cluster domain |

## Headless Services

A **headless service** (`clusterIP: None`) makes DNS return the **pod IPs** directly instead of one service IP. This suits stateful apps, such as databases, where each pod must be addressed individually.

## CoreDNS

CoreDNS watches the Kubernetes API for service and pod changes, updates DNS records automatically, and runs as a Deployment in the `kube-system` namespace. Check its pods with:

```bash
kubectl get pods -n kube-system -l k8s-app=kube-dns
```

**Analogy:** a class contact list. You say "Call Alice" (the service name) and the phone (DNS) dials the right number for you.
