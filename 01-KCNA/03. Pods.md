# 03. Pods

## What Is a Pod?

A **pod is the most basic unit of Kubernetes**, just as letters are the basic unit of the English language or the cell is the basic unit of the human body.

- Kubernetes does **not** manage containers directly. It manages them **through pods**: it first creates a pod, then deploys containers inside it.
- A pod manages the container **as a whole**, not what happens inside the container.
- Kubernetes gives the IP address and configuration to the **pod**, not to the individual container.
- Usually one pod runs one container, but a pod **can run multiple containers**.

**Hierarchy:** App → Container → Pod → Node → Cluster

## Pod Definition in YAML

```yaml
apiVersion: v1          # apps/v1 for objects such as ReplicaSets and Deployments
kind: Pod               # the type of object we want to create
metadata:
  name: my-pod
  labels:
    app: myapp
    type: front-end
spec:
  containers:
  - name: nginx-container
    image: nginx
```

Create the pod from the file:

```bash
kubectl create -f <name-of-your-file>.yml
```

The four top-level fields every Kubernetes object needs:

| Field | Purpose |
|---|---|
| `apiVersion` | Which API version defines this object |
| `kind` | The object type (Pod, ReplicaSet, Deployment, ...) |
| `metadata` | Name and labels that identify the object |
| `spec` | The desired state, such as which containers to run |
