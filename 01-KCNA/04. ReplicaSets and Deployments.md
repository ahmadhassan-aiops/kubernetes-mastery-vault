# 04. ReplicaSets and Deployments

## ReplicaSet

A ReplicaSet keeps a fixed number of identical pods running at all times. If a pod dies, the ReplicaSet creates a new one to get back to the desired count.

```yaml
apiVersion: apps/v1
kind: ReplicaSet
metadata:
  name: myapp-replicaset
  labels:
    app: myapp
spec:
  replicas: 3            # how many pods to keep running
  selector:
    matchLabels:
      app: myapp         # which pods this ReplicaSet manages
  template:              # the pod blueprint
    metadata:
      labels:
        app: myapp
    spec:
      containers:
      - name: nginx
        image: nginx
```

Key parts:

- **`replicas`:** the desired number of pods.
- **`selector.matchLabels`:** must match the labels in the pod template.
- **`template`:** the pod definition used to create each replica.

## Deployment

A Deployment sits one level above a ReplicaSet. It uses the same structure (with `kind: Deployment`), creates and manages ReplicaSets for you, and adds **rolling updates and rollbacks**, so you can change the image version without downtime.

**Hierarchy:** Deployment → ReplicaSet → Pods
