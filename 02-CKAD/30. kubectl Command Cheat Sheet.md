# 30. kubectl Command Cheat Sheet

A quick reference for the CKAD exam, grouped by topic. Each section links to the hands-on topic where the commands are used.

## Pods

```bash
kubectl run nginx --image=nginx                          # create a pod
kubectl run redis --image=redis:alpine --labels="tier=db"
kubectl get pods                                         # list pods
kubectl get pods <pod>                                   # one pod
kubectl get pods -o wide                                 # with IP and node
kubectl describe pod <pod>                               # full details and events
kubectl describe pod <pod> | grep -i image               # which image a pod uses
kubectl create -f pod.yaml        # or: kubectl apply -f pod.yaml
kubectl run redis --image=redis --dry-run=client -o yaml > pod.yaml   # generate YAML
kubectl exec <pod> -- whoami                             # run a command in a pod
```

## Deployments, Rollouts and Rollbacks

```bash

kubectl create deployment my-deploy --image=nginx --replicas=3 --dry-run=client -o yaml > deploy.yaml
kubectl get deployments

kubectl rollout undo deployment/mydeployment
```

## Namespaces

```bash
kubectl get namespaces            # or: kubectl get ns
kubectl create namespace <ns>     # or: kubectl create -f namespace.yaml
kubectl get pods --namespace=<ns> # or: kubectl -n <ns> get pods
kubectl -n <ns> get pods --no-headers
kubectl create -f pod.yaml --namespace=<ns>
kubectl get pods --all-namespaces
kubectl get pods --all-namespaces | grep blue            # find a pod anywhere
kubectl get ns --no-headers | wc -l                      # count namespaces
kubectl config set-context $(kubectl config current-context) --namespace=<ns>
```

Reach a Service in another namespace with its full name: `db-service.dev.svc.cluster.local`.

## Services

```bash
kubectl get services
kubectl describe service <svc>
kubectl -n <ns> get svc
minikube service myapp-service --url                     # service URL on Minikube

# ClusterIP for pod "redis" on 6379 (uses the pod's labels as selector)
kubectl expose pod redis --port=6379 --name redis-service --dry-run=client -o yaml

# NodePort for pod "nginx" (uses pod labels, but you can't set the nodePort here)
kubectl expose pod nginx --port=80 --name nginx-service --type=NodePort --dry-run=client -o yaml

# create service assumes selector app=<name>; can set a nodePort
kubectl create service clusterip redis --tcp=6379:6379 --dry-run=client -o yaml
kubectl create service nodeport nginx --tcp=80:80 --node-port=30080 --dry-run=client -o yaml

# a NodePort Service for a deployment, saved to a file
kubectl expose deployment simple-webapp-deployment --name=webapp-service \
  --target-port=8080 --type=NodePort --port=8080 --dry-run=client -o yaml > svc.yaml
```

**Tip:** prefer `kubectl expose`. If you need a specific nodePort, generate the YAML, add the nodePort by hand, then apply.

```yaml
apiVersion: v1
kind: Service
metadata:
  name: myapp-service
spec:
  type: NodePort
  selector:
    app: myapp
    type: front-end
  ports:
  - targetPort: 80
    port: 80
    nodePort: 30008
```

## ConfigMaps

```bash
kubectl create configmap <cm> --from-literal=key=value
kubectl create configmap <cm> \
  --from-literal=key1=value1 \
  --from-literal=key2=value2
kubectl create configmap <cm> --from-file=app_config.properties
kubectl get configmaps
kubectl describe configmap <cm>
kubectl explain pods --recursive | grep envFrom -A3      # find where a field goes
```

```yaml
containers:
- name: nginx
  image: nginx
  ports:
  - containerPort: 8080
  envFrom:
  - configMapRef:
      name: <cm>
```

## Secrets

```bash
kubectl create secret generic <secret> --from-literal=key=value
kubectl create secret generic app-secret --from-literal=DB_HOST=mysql
kubectl create secret generic app-secret --from-file=app_secret.properties
kubectl get secrets
kubectl describe secret <secret>
echo -n 'mysql' | base64                 # encode a value
echo -n 'bXlzcWw=' | base64 --decode     # decode it
```

```yaml
  envFrom:
  - secretRef:
      name: <secret>
```

## Taints and Tolerations

```bash
kubectl taint nodes <node> key=value:<effect>      # NoSchedule | PreferNoSchedule | NoExecute
kubectl taint nodes node1 app=blue:NoSchedule
kubectl taint nodes controlplane node-role.kubernetes.io/control-plane:NoSchedule-   # remove
kubectl describe node <node> | grep Taint
kubectl explain pod --recursive | grep -A5 tolerations
```

```yaml
spec:
  tolerations:
  - key: "app"
    operator: "Equal"
    value: "blue"
    effect: "NoSchedule"
```

## Node Selectors and Node Affinity

```bash
kubectl label nodes node01 size=Large
```

```yaml
spec:
  nodeSelector:
    size: Large
---
spec:
  affinity:
    nodeAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        nodeSelectorTerms:
        - matchExpressions:
          - key: size
            operator: In        # In | NotIn | Exists (no values needed)
            values:
            - Large
```

## Jobs and CronJobs

```bash
kubectl get jobs
kubectl logs <job-pod>
kubectl delete job <job>
kubectl get cronjobs
```

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: math-add-job
spec:
  completions: 3
  parallelism: 3
  template:
    spec:
      containers:
      - name: math-add
        image: ubuntu
        command: ['expr', '3', '+', '2']
      restartPolicy: Never
---
apiVersion: batch/v1
kind: CronJob
metadata:
  name: reporting-cron-job
spec:
  schedule: "*/1 * * * *"
  jobTemplate:
    spec:
      completions: 3
      parallelism: 3
      template:
        spec:
          containers:
          - name: math-add
            image: ubuntu
            command: ['expr', '3', '+', '2']
          restartPolicy: Never
```
