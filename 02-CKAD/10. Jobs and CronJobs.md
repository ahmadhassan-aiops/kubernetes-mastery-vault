# 10. Jobs and CronJobs

## What Is a Job?

A **Job** runs a containerized task **to completion**.

Think of a calculator solving `3 + 2 = 5`: it starts, does one thing and stops. Docker can run such a container once and exit. Kubernetes acts like a **manager of many calculators**, running the task in parallel or one after another, and a Job makes sure the task **finishes successfully**, retrying failed pods if needed. That makes Jobs ideal for batch and one-off work.

**Restart policies for Jobs:**

| Policy | Behaviour |
|---|---|
| `Never` | Don't restart a failed container; create a new pod instead |
| `OnFailure` | Restart the container in the same pod if it fails |
| `Always` | **Not allowed** for Jobs (used by Deployments and similar controllers) |

**Key fields:**

| Field | Meaning |
|---|---|
| `completions` | How many successful runs you need |
| `parallelism` | How many pods may run at the same time |
| `backoffLimit` | How many times to retry failed pods |
| `activeDeadlineSeconds` | Time limit for the whole Job |

Example: `completions: 5` with `parallelism: 2` runs two pods at a time until five have succeeded.

## Job 1: A Single Run

```console
[root@client1 ahmad]# kubectl get jobs -A
No resources found
```

```yaml
# job-test.yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: my-job
  namespace: default
spec:
  backoffLimit: 4                 # retry failed pods up to 4 times
  activeDeadlineSeconds: 10       # job timeout in seconds
  template:
    spec:
      containers:
      - name: example-job
        image: busybox:stable
        command: ["echo", "This is a Test Job!!"]   # what the container runs
      restartPolicy: Never        # don't restart the container if it fails
```


## Job 2: Five Completions

Add `completions: 5` and raise the deadline to 40 seconds. A Job's pod template can't be changed in place, so use `replace --force` (delete and recreate):

```yaml
spec:
  backoffLimit: 4
  activeDeadlineSeconds: 40
  completions: 5
```

## Job 3: Retries and Parallelism (Throwing a Die)

The `kodekloud/throw-dice` image rolls a die and **succeeds only on a 6**, so some pods fail and must be retried.

```yaml
# job-pod.yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: dice-job
  namespace: default
spec:
  backoffLimit: 60           # retry failed pods up to 60 times
  completions: 2             # total successful runs required
  parallelism: 3             # run up to 3 pods at the same time
  template:
    spec:
      containers:
      - name: dice-job-container
        image: kodekloud/throw-dice
      restartPolicy: Never   # required for Jobs
```

```console
[root@client1 ahmad]# kubectl apply -f job-pod.yaml
job.batch/dice-job created
[root@client1 ahmad]# kubectl get jobs
NAME       STATUS    COMPLETIONS   DURATION   AGE
dice-job   Running   0/2           4s         4s
[root@client1 ahmad]# kubectl get jobs
NAME       STATUS    COMPLETIONS   DURATION   AGE
dice-job   Running   1/2           10s        10s
[root@client1 ahmad]# kubectl get jobs
NAME       STATUS     COMPLETIONS   DURATION   AGE
dice-job   Complete   2/2           22s        29s

[root@client1 ahmad]# kubectl describe job dice-job
Parallelism:      3
Completions:      2
Backoff Limit:    60
Duration:         22s
Pods Statuses:    0 Active (0 Ready) / 2 Succeeded / 1 Failed
```

The logs prove it: the failed pod rolled a 2, the successful ones rolled 6s.

```console
[root@client1 ahmad]# kubectl get pods

[root@client1 ahmad]# kubectl logs dice-job-fp7md

[root@client1 ahmad]# kubectl logs dice-job-vml6z

[root@client1 ahmad]# kubectl logs dice-job-z57zk

```

## CronJobs

A **CronJob** creates Jobs on a **schedule**, using standard cron syntax (`minute hour day month weekday`).

```yaml
# cron-job.yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: my-cronjob
  namespace: default
spec:
  schedule: "*/1 * * * *"           # every minute
  jobTemplate:
    spec:
      backoffLimit: 5               # retry failed pods up to 5 times
      activeDeadlineSeconds: 20     # max time for one job run
      template:
        spec:
          containers:
          - name: test-cronjob-container
            image: busybox:stable
            command: ["echo", "This is a Test CronJob!!"]
          restartPolicy: Never      # required for Jobs and CronJobs
```

One Job (and pod) appears every minute:

```console
[root@client1 ahmad]# kubectl get cronjob
```
