# 04. Init Containers

An **init container** runs **to completion before** the main containers start. It's used for setup work such as waiting for a dependency, preparing files or running migrations.

```yaml
# init-container.yaml
apiVersion: v1
kind: Pod
metadata:
  name: init-container-pod
spec:
  initContainers:
  - name: init-container
    image: busybox:stable
    command: ["sh", "-c", "sleep 60"]
  containers:
  - name: main-container
    image: nginx:stable
```

Watch the pod move through the init phase. Nginx starts only after the 60-second init container finishes:

```console
[root@client1 ahmad]# kubectl get po -w
NAME                 READY   STATUS            RESTARTS   AGE
init-container-pod   0/1     Init:0/1          0          57s
init-container-pod   0/1     PodInitializing   0          62s
init-container-pod   1/1     Running           0          63s
```

| Status | Meaning |
|---|---|
| `Init:0/1` | 0 of 1 init containers finished |
| `PodInitializing` | Init done, main containers starting |
| `Running` | Main container is up |

> An init container does **not** make a pod multi-container: `READY` shows `1/1`, because only the main container counts once it is running.
