# 13. Environment Variables and ConfigMaps

A **ConfigMap** stores **non-confidential** configuration as key-value pairs. Pods can consume it as environment variables, command-line arguments or mounted files. This keeps configuration **separate from the container image**, so you can change settings without rebuilding the image. Use ConfigMaps for app settings, URLs and feature flags; use [Secrets](14.%20Secrets.md) for sensitive data.

Reference: [Define environment variables for a container](https://kubernetes.io/docs/tasks/inject-data-application/define-environment-variable-container/)

## Step 1: A Plain Environment Variable

The `kodekloud/webapp-color` app paints its page with the colour in `APP_COLOR`.

```yaml
# env-pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: test-pod
  labels:
     app: color
  namespace: default
spec:
  containers:
    - name: test-container
      image: kodekloud/webapp-color
      env:
        - name: APP_COLOR
          value: pink
```

```console
[root@client1 ahmad]# kubectl apply -f env-pod.yaml
pod/test-pod created
[root@client1 ahmad]# kubectl get po
NAME       READY   STATUS    RESTARTS   AGE
test-pod   1/1     Running   0          6s
```

Expose it and check the endpoint:

```console
[root@client1 ahmad]# kubectl expose po test-pod --port 8080 --name test-svc --dry-run=client -o yaml > env_svc.yaml
[root@client1 ahmad]# cat env_svc.yaml
apiVersion: v1
kind: Service
metadata:
  creationTimestamp: null
  labels:
    app: color
  name: test-svc
spec:
  ports:
  - port: 8080
    protocol: TCP
    targetPort: 8080
  selector:
    app: color
status:
  loadBalancer: {}

[root@client1 ahmad]# kubectl describe svc test-svc
Name:                     test-svc
Selector:                 app=color
Type:                     ClusterIP
IP:                       10.96.198.62
Port:                     <unset>  8080/TCP
TargetPort:               8080/TCP
Endpoints:                10.244.1.4:8080
```

```console
[root@client1 ahmad]# kubectl port-forward pod/test-pod 5555:8080
Forwarding from 127.0.0.1:5555 -> 8080
Forwarding from [::1]:5555 -> 8080
Handling connection for 5555
```

`127.0.0.1:5555` shows a **pink** page. Change the value and recreate the pod to change the colour.

## Step 2: Creating ConfigMaps

### Imperatively, from literals

```console
[root@client1 ahmad]# kubectl create cm test-config --from-literal=APP_COLOR=green --from-literal=APP_TYPE=prod
configmap/test-config created
[root@client1 ahmad]# kubectl describe cm test-config
Name:         test-config
Namespace:    default

Data
====
APP_TYPE:
----
prod

APP_COLOR:
----
green
```

### Declaratively, from YAML

```yaml
# test-config.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: test-config-map
data:
  NAME: ahmad
  ORG: EQUALS
  COURSE: CKAD
```

```console
[root@client1 ahmad]# kubectl apply -f test-config.yaml
configmap/test-config-map created
[root@client1 ahmad]# kubectl get cm
NAME               DATA   AGE
kube-root-ca.crt   1      5d20h
test-config        2      3m28s
test-config-map    3      7s
[root@client1 ahmad]# kubectl describe cm test-config-map
Data
====
ORG:
----
EQUALS

COURSE:
----
CKAD

NAME:
----
ahmad
```

Other ways to create one: `--from-file=app_config.properties` loads a whole file.

## Step 3: Injecting a ConfigMap into a Pod

```yaml
# web-config.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: web-config-map
data:
  APP_COLOR: darkblue
```

`envFrom` loads **every key** of the ConfigMap as an environment variable:

```yaml
# env-pod2.yaml
apiVersion: v1
kind: Pod
metadata:
  name: web-pod
  labels:
    web: color
  namespace: default
spec:
  containers:
    - name: test-container
      image: kodekloud/webapp-color
      envFrom:
        - configMapRef:
            name: web-config-map
```

```console
[root@client1 ahmad]# kubectl apply -f web-config.yaml
configmap/web-config-map created
[root@client1 ahmad]# kubectl apply -f env-pod2.yaml
pod/web-pod created
[root@client1 ahmad]# kubectl get po
NAME       READY   STATUS    RESTARTS   AGE
test-pod   1/1     Running   0          26m
web-pod    1/1     Running   0          11s

[root@client1 ahmad]# kubectl describe po web-pod
Containers:
  test-container:
    Image:          kodekloud/webapp-color
    State:          Running
    Environment Variables from:
      web-config-map  ConfigMap  Optional: false
```

```console
[root@client1 ahmad]# kubectl expose po web-pod --port 8080 --name web-svc
service/web-svc exposed
[root@client1 ahmad]# kubectl port-forward pod/web-pod 2222:8080
Forwarding from 127.0.0.1:2222 -> 8080
Forwarding from [::1]:2222 -> 8080
Handling connection for 2222
```

`127.0.0.1:2222` now shows a **dark blue** page, driven entirely by the ConfigMap. (The earlier `test-svc` had to be deleted first before this worked.)

## Ways to Use a ConfigMap

| Method | YAML |
|---|---|
| All keys as env vars | `envFrom: - configMapRef: name: <cm>` |
| One key as an env var | `env: - name: APP_COLOR valueFrom: configMapKeyRef: name: <cm> key: APP_COLOR` |
| As files in a volume | `volumes: - name: cfg configMap: name: <cm>` plus a `volumeMount` |
