# 19. Node Selectors

A **node selector** is the simplest way to make a pod run only on nodes with a specific **label**. Kubernetes compares the pod's `nodeSelector` key-value pairs with each node's labels, and only matching nodes are eligible.

**Example scenario:** your cluster has standard nodes and high-memory nodes labelled `type=high-memory`. A database pod needs lots of RAM, so you label the right nodes (`kubectl label nodes <node> type=high-memory`) and add `nodeSelector: type: high-memory` to the pod. Kubernetes then only schedules it on nodes that can meet its memory needs.

## Lab: A Three-Node Cluster

# kind-config.yaml
kind: Cluster

nodes:

  - role: worker

### Step 1: Without a node selector

```yaml
# without-node-selector-pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: node-selector-pod
spec:
  containers:
  - name: nginx-container
    image: nginx
```

```console
[root@client1 ahmad]# kubectl apply -f without-node-selector-pod.yaml
pod/node-selector-pod created
[root@client1 ahmad]# kubectl get po -o wide
NAME                READY   STATUS              RESTARTS   AGE   IP       NODE          NOMINATED NODE   READINESS GATES
node-selector-pod   0/1     ContainerCreating   0          10s   <none>   kind-worker   <none>           <none>
```

The scheduler picked `kind-worker` on its own.

### Step 2: Label a node and use a node selector

```yaml
# node-selector-pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: node-selector-pod-2
spec:
  containers:
  - name: nginx-container
    image: nginx
  nodeSelector:
    cpu: large
```

## Commands

```bash
kubectl label nodes <node> key=value        # add a label
kubectl label nodes <node> key-             # remove a label
kubectl get nodes <node> --show-labels      # list a node's labels
```

> Node selectors only support **exact** matches. For "prefer" rules or operators such as `In`, `NotIn` and `Exists`, use [node affinity](20.%20Node%20Affinity.md).
