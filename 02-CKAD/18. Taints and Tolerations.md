# 18. Taints and Tolerations

**Taints** are applied to **nodes** to repel pods; **tolerations** are applied to **pods** to let them be scheduled on nodes with matching taints. They keep certain workloads off specific nodes (such as GPU or critical system nodes) unless explicitly allowed.

## Taint Effects

| Effect | Behaviour |
|---|---|
| **NoSchedule** | The most common. No new pod is scheduled on the node unless it tolerates the taint. A **hard** rule at scheduling time. |
| **PreferNoSchedule** | A **soft** rule. Kubernetes tries to avoid the node but may still use it if there's no better option. |
| **NoExecute** | Affects **new and running** pods: blocks new ones and **evicts existing pods** that don't tolerate it. Used for node failures and maintenance. |

> **Cordoning** a node marks it unschedulable, so no new pods land there, but pods already running are not affected. It's usually done before draining a node for maintenance.

## The Control-Plane Node Is Always Tainted

```console
[root@client1 ahmad]# kubectl describe node my-cluster-control-plane | grep Taint
Taints:             node-role.kubernetes.io/control-plane:NoSchedule
[root@client1 ahmad]# kubectl describe node my-cluster-worker | grep Taint
Taints:             <none>
```

That's why normal pods never run on the control plane.

## Lab: Mosquitoes, Bees and Bug Spray

### Step 1: Spray the worker node

```console
[root@client1 ahmad]# kubectl taint node my-cluster-worker spray=mortein:NoSchedule
node/my-cluster-worker tainted
[root@client1 ahmad]# kubectl describe node my-cluster-worker | grep Taint
Taints:             spray=mortein:NoSchedule
```

### Step 2: A pod without a toleration (the mosquito)

```console
[root@client1 ahmad]# kubectl run mosquito --image nginx
pod/mosquito created
[root@client1 ahmad]# kubectl get po
NAME       READY   STATUS    RESTARTS   AGE
mosquito   0/1     Pending   0          9s
[root@client1 ahmad]# kubectl describe po mosquito
Events:
  Type     Reason            Age   From               Message
  ----     ------            ----  ----               -------
  Warning  FailedScheduling  34s   default-scheduler  0/2 nodes are available: 1 node(s) had untolerated taint {node-role.kubernetes.io/control-plane: },
1 node(s) had untolerated taint {spray: mortein}. preemption: 0/2 nodes are available: 2 Preemption is not helpful for scheduling.
```

Both nodes are tainted and the mosquito tolerates neither, so it stays Pending.

### Step 3: A pod with a toleration (the bee)

```console
[root@client1 ahmad]# kubectl run bee --image=nginx --dry-run=client -o yaml > bee.pod.yaml
```

```yaml
# bee.pod.yaml
apiVersion: v1
kind: Pod
metadata:
  labels:
    run: bee
  name: bee
spec:
  containers:
  - image: nginx
    name: bee
    resources: {}
  dnsPolicy: ClusterFirst
  restartPolicy: Always
  tolerations:
    - key: spray
      operator: Equal
      value: mortein
      effect: NoSchedule
```

```console
[root@client1 ahmad]# kubectl replace --force -f bee.pod.yaml
pod/bee replaced
[root@client1 ahmad]# kubectl get po
NAME       READY   STATUS    RESTARTS   AGE
bee        1/1     Running   0          4s
mosquito   0/1     Pending   0          8m46s
```

The bee tolerates the spray, so it runs on the worker node.

### Step 4: Remove the control-plane taint

A trailing `-` removes a taint:

```console
[root@client1 ahmad]# kubectl taint node my-cluster-control-plane node-role.kubernetes.io/control-plane:NoSchedule-
node/my-cluster-control-plane untainted
[root@client1 ahmad]# kubectl get po -o wide
NAME       READY   STATUS              RESTARTS   AGE    IP           NODE                       NOMINATED NODE   READINESS GATES
bee        1/1     Running             0          6m5s   10.244.1.7   my-cluster-worker          <none>           <none>
mosquito   0/1     ContainerCreating   0          14m    <none>       my-cluster-control-plane   <none>           <none>
```

The mosquito is scheduled on the **control-plane** node: it's now untainted, while the worker still has the spray the mosquito doesn't tolerate.

### Step 5: Re-add `NoSchedule` (running pods stay)

```console
[root@client1 ahmad]# kubectl taint node my-cluster-control-plane node-role.kubernetes.io/control-plane:NoSchedule
node/my-cluster-control-plane tainted
[root@client1 ahmad]# kubectl get po -o wide
NAME       READY   STATUS              RESTARTS   AGE     IP           NODE                       NOMINATED NODE   READINESS GATES
bee        1/1     Running             0          9m32s   10.244.1.7   my-cluster-worker          <none>           <none>
mosquito   0/1     ContainerCreating   0          18m     <none>       my-cluster-control-plane   <none>           <none>
```

The mosquito **stays**: `NoSchedule` only affects scheduling, not pods already placed. Delete it and create it again, though, and it can't be scheduled:

```console
[root@client1 ahmad]# kubectl delete po mosquito
pod "mosquito" deleted
[root@client1 ahmad]# kubectl run mosquito --image=nginx
pod/mosquito created
[root@client1 ahmad]# kubectl get po
NAME       READY   STATUS    RESTARTS   AGE
bee        1/1     Running   0          16m
mosquito   0/1     Pending   0          6s
```

### Step 6: `NoExecute` evicts pods

```console
[root@client1 ahmad]# kubectl taint node my-cluster-control-plane node-role.kubernetes.io/control-plane:NoExecute
node/my-cluster-control-plane tainted
[root@client1 ahmad]# kubectl get po
NAME   READY   STATUS    RESTARTS   AGE
bee    1/1     Running   0          19m
```

With `NoExecute`, the mosquito is **removed** entirely.

## Commands

```bash
kubectl taint nodes <node> key=value:NoSchedule     # add a taint
kubectl taint nodes <node> key=value:NoSchedule-    # remove it
kubectl describe node <node> | grep Taint           # check taints
kubectl explain pod --recursive | grep -A5 tolerations
```

> Taints **repel** pods but don't **attract** them. To send a pod to a specific node, combine a toleration with a [node selector](19.%20Node%20Selectors.md) or [node affinity](20.%20Node%20Affinity.md).
