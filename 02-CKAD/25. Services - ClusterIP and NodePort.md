# 25. Services: ClusterIP and NodePort

## What Is a Service?

Pods come and go, and their IPs change. A **Service** gives a group of pods a **stable address**, like a permanent doorway to them, and load-balances traffic across them.

| Type | Reachable from | Use for |
|---|---|---|
| **ClusterIP** (default) | Inside the cluster only | Pod-to-pod communication (frontend → backend) |
| **NodePort** | Outside, through `<NodeIP>:<nodePort>` on every node | Simple external access, labs |
| **LoadBalancer** | A public IP from the cloud provider | Production external access in the cloud |

## NodePort: Three Ports

| Field | Required? | Meaning |
|---|---|---|
| `port` | Yes | The Service's own port inside the cluster |
| `targetPort` | No (defaults to `port`) | The port the **pod** listens on |
| `nodePort` | No (random from **30000 to 32767**) | The port opened on **every node** |

Reach the app at `<NodeIP>:<nodePort>`; Kubernetes forwards the traffic to a matching pod. Whether the pods share one node or are spread across several, the traffic is spread between them.

## ClusterIP in Multi-Tier Apps

Imagine three tiers: **frontend**, **backend** and **Redis**.

- Frontend pods call the backend through the **backend ClusterIP Service**.
- Backend pods call Redis through the **redis ClusterIP Service**.
- Nobody needs to know pod IPs; they just use the Service name.

**Why ClusterIP?** Service IPs don't change (stable access), traffic is spread evenly (built-in load balancing), you connect by name (`http://backend`), and Kubernetes DNS finds Services automatically.

In short, a ClusterIP Service is like a **private phone number inside the cluster** that always reaches the right group of pods.

## Lab: Three Web Pods Behind One Service

```yaml
# deploy.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: webapp-frontend
  labels:
    app: frontend
spec:
  replicas: 3
  selector:
    matchLabels:
      app: frontend
  template:
    metadata:
      labels:
        app: frontend
    spec:
      containers:
      - name: webapp
        image: kodekloud/simple-webapp:red
        ports:
        - containerPort: 8080
```

### ClusterIP

```yaml
# clusterip-svc.yaml
apiVersion: v1
kind: Service
metadata:
  name: webapp-clusterip-service
spec:
  selector:
    app: frontend
  ports:
  - protocol: TCP
    port: 8080
    targetPort: 8080
  type: ClusterIP
```

```console
[root@client1 ahmad]# kubectl apply -f clusterip-svc.yaml
service/webapp-clusterip-service created
[root@client1 ahmad]# kubectl describe svc webapp-clusterip-service
Name:                     webapp-clusterip-service
Selector:                 app=frontend
Type:                     ClusterIP
IP:                       10.96.43.93
Port:                     <unset>  8080/TCP
TargetPort:               8080/TCP
Endpoints:                10.244.2.2:8080,10.244.1.3:8080,10.244.2.3:8080
```

All three pod IPs are endpoints. From inside the cluster (the control-plane container):

```console
[root@client1 ahmad]# docker exec -it kind-control-plane bash

<!doctype html>
```

### NodePort

```yaml
# nodeport-svc.yaml
apiVersion: v1
kind: Service
metadata:
  name: webapp-nodeport-service
spec:
  selector:
    app: frontend
  ports:
  - protocol: TCP
    port: 8080
    targetPort: 8080
    nodePort: 30080
  type: NodePort
```

```console
[root@client1 ahmad]# kubectl apply -f nodeport-svc.yaml
service/webapp-nodeport-service created
[root@client1 ahmad]# kubectl describe svc webapp-nodeport-service
Selector:                 app=frontend
Type:                     NodePort
IP:                       10.96.194.202
Port:                     <unset>  8080/TCP
TargetPort:               8080/TCP
NodePort:                 <unset>  30080/TCP
Endpoints:                10.244.2.3:8080,10.244.2.2:8080,10.244.1.3:8080
```

```console
[root@client1 ahmad]# kubectl get nodes -o wide
```

This time a **different pod** (`jxtxk`) answered: the Service load-balances between the replicas. Note that the request went to the **control-plane** node's IP, which runs none of the pods; a NodePort is open on every node and forwards traffic wherever the pods are. You can also open `172.25.0.3:30080` in a browser on the VM.
