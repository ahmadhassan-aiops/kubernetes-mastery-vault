# 09. Namespaces, Contexts and Resource Quotas

A **namespace** separates resources inside one cluster, for example to keep `prod` and `testing` apart. Kubernetes creates some namespaces by default, you can create your own, and you can give each namespace its own resource limits (CPU, memory, number of pods).

## Default Namespaces

`namespaces`, `namespace` and `ns` all work:

```console
[root@client1 ahmad]# kubectl get ns
NAME                 STATUS   AGE
default              Active   2d15h
kube-node-lease      Active   2d15h
kube-public          Active   2d15h
kube-system          Active   2d15h
local-path-storage   Active   2d15h
```

| Namespace | Purpose |
|---|---|
| `default` | Where your objects go if you don't specify a namespace |
| `kube-system` | Control plane and system components |
| `kube-public` | Readable by everyone, rarely used |
| `kube-node-lease` | Node heartbeat leases |
| `local-path-storage` | kind's local storage provisioner |

`kube-system` holds the cluster's own components:

## kubeconfig and Contexts

`kubectl config` manages the kubeconfig file. Its loading order:

1. If `--kubeconfig` is set, only that file is used.
2. Otherwise, if `$KUBECONFIG` is set, those files are merged.
3. Otherwise, `${HOME}/.kube/config` is used.

Useful subcommands: `current-context`, `get-contexts`, `get-clusters`, `use-context`, `set-context`, `set-credentials`, `view`.

```console
[root@client1 ahmad]# kubectl config current-context
kind-my-cluster
[root@client1 ahmad]# kubectl config get-clusters
NAME
kind-my-cluster
[root@client1 ahmad]# kubectl config get-contexts
CURRENT   NAME              CLUSTER           AUTHINFO          NAMESPACE
*         kind-my-cluster   kind-my-cluster   kind-my-cluster   default
```

### Switching the default namespace

```console
[root@client1 ahmad]# kubectl create namespace cloudops
namespace/cloudops created
[root@client1 ahmad]# kubectl config set-context $(kubectl config current-context) --namespace=cloudops
Context "kind-my-cluster" modified.
[root@client1 ahmad]# kubectl get pods
No resources found in cloudops namespace.

[root@client1 ahmad]# kubectl config set-context $(kubectl config current-context) --namespace=kube-system
Context "kind-my-cluster" modified.
[root@client1 ahmad]# kubectl config get-contexts
CURRENT   NAME              CLUSTER           AUTHINFO          NAMESPACE
*         kind-my-cluster   kind-my-cluster   kind-my-cluster   kube-system

[root@client1 ahmad]# kubectl config set-context $(kubectl config current-context) --namespace=default
Context "kind-my-cluster" modified.
```

To act on another namespace without switching, add `-n <namespace>` (or `--namespace`) to any command, for example `kubectl -n dev delete pod db-pod`.

## The Same Pod Name in Different Namespaces

Names only need to be unique **within** a namespace.

```yaml
# pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: cloudops-pod
spec:
  containers:
    - name: nginx
      image: nginx
```

Apply it with `-n`, or set `metadata.namespace` in the file:

```console
[root@client1 ahmad]# kubectl apply -f pod.yaml -n default
pod/cloudops-pod created
[root@client1 ahmad]# kubectl apply -f pod.yaml -n cloudops
pod/cloudops-pod created
```

```yaml
metadata:
  name: cloudops-pod
  namespace: alpha-namespace
```

```console
[root@client1 ahmad]# kubectl apply -f pod.yaml
pod/cloudops-pod created
[root@client1 ahmad]# kubectl get pods -n alpha-namespace
NAME           READY   STATUS    RESTARTS   AGE
cloudops-pod   1/1     Running   0          9s
```

> If the namespace in the file doesn't exist, the apply fails with `namespaces "<name>" not found`. Create the namespace first.

Find a pod by name across all namespaces:

```console
[root@client1 ahmad]# kubectl get pods --all-namespaces --field-selector metadata.name=cloudops-pod
NAMESPACE         NAME           READY   STATUS    RESTARTS   AGE
alpha-namespace   cloudops-pod   1/1     Running   0          48s
cloudops          cloudops-pod   1/1     Running   0          7m19s
default           cloudops-pod   1/1     Running   0          9m46s
```

## ResourceQuota: Limiting a Namespace

```yaml
# resource-quota.yaml
apiVersion: v1
kind: ResourceQuota
metadata:
  name: compute-quota
  namespace: cloudops
spec:
  hard:
    pods: "2"
    requests.cpu: "2"
    requests.memory: 2Gi
    limits.cpu: "3"
    limits.memory: 3Gi
```

```console
[root@client1 ahmad]# kubectl apply -f resource-quota.yaml
resourcequota/compute-quota created
[root@client1 ahmad]# kubectl describe ns cloudops
Name:         cloudops
Labels:       kubernetes.io/metadata.name=cloudops
Status:       Active

Resource Quotas
  Name:            compute-quota
  Resource         Used  Hard
  --------         ---   ---
  limits.cpu       0     3
  limits.memory    0     3Gi
  pods             1     2
  requests.cpu     0     2
  requests.memory  0     2Gi

No LimitRange resource.

[root@client1 ahmad]# kubectl describe ns alpha-namespace
Name:         alpha-namespace
Status:       Active

No resource quota.

No LimitRange resource.
```

**Test 1: a pod without resources is rejected.** Once a quota covers CPU and memory, every pod in the namespace must declare requests and limits:

```console
[root@client1 ahmad]# kubectl apply -f pod.yaml
Error from server (Forbidden): error when creating "pod.yaml": pods "cloudops-pod-2" is forbidden:
failed quota: compute-quota: must specify limits.cpu for: nginx; limits.memory for: nginx; requests.cpu for: nginx; requests.memory for: nginx
```

**Test 2: add requests and limits, and the pod is accepted.**

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: cloudops-pod-2
  namespace: cloudops
spec:
  containers:
    - name: nginx
      image: nginx
      resources:
        requests:
          memory: "1Gi"
          cpu: "1"
        limits:
          memory: "1.5Gi"
          cpu: "2"
```

```console
[root@client1 ahmad]# kubectl apply -f pod.yaml
pod/cloudops-pod-2 created
[root@client1 ahmad]# kubectl get po -n cloudops
NAME             READY   STATUS    RESTARTS   AGE
cloudops-pod     1/1     Running   0          20m
cloudops-pod-2   1/1     Running   0          45s
```

**Test 3: a third pod exceeds the quota** (2 pods max, and `limits.cpu` would go above 3):

```console
[root@client1 ahmad]# kubectl apply -f pod.yaml
Error from server (Forbidden): error when creating "pod.yaml": pods "cloudops-pod-3" is forbidden: exceeded quota: compute-quota,
requested: limits.cpu=2,pods=1, used: limits.cpu=2,pods=2, limited: limits.cpu=3,pods=2
```

## Reaching Services Across Namespaces

### A test app in `default`

```yaml
# test-pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: test-pod
  namespace: default
  labels:
    name: blue-55
spec:
  containers:
  - name: internal
    image: kodekloud/webapp-conntest
    env:
    - name: APP_NAME
      value: "Blue - Marketing Application"
    - name: BG_COLOR
      value: blue
    ports:
    - containerPort: 8080
      protocol: TCP
```

```yaml
# test-service.yaml
apiVersion: v1
kind: Service
metadata:
  name: test-service
  namespace: default
spec:
  type: NodePort
  selector:
    name: blue-55
  ports:
  - protocol: TCP
    port: 8080
    targetPort: 8080
```

```console
[root@client1 ahmad]# kubectl apply -f test-pod.yaml
pod/test-pod created
[root@client1 ahmad]# kubectl apply -f test-service.yaml
service/test-service created

[root@client1 ahmad]# kubectl describe svc test-service

Port:                     <unset>  8080/TCP
TargetPort:               8080/TCP
NodePort:                 <unset>  30609/TCP
Endpoints:                10.244.1.10:8080
```

### A Redis database in the same namespace

```yaml
# db-test-pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: db-pod
  namespace: default
  labels:
    name: blue-55
spec:
  containers:
  - name: redis
    image: redis:alpine
    env:
    - name: REDIS_ROOT_PASSWORD
      value: paswr
    ports:
    - containerPort: 6379
      protocol: TCP
```

```yaml
# db-test-svc.yaml
apiVersion: v1
kind: Service
metadata:
  name: db-service
  namespace: default
spec:
  type: NodePort
  selector:
    name: blue-55
  ports:
  - protocol: TCP
    port: 6379
    targetPort: 6379
```

```console
[root@client1 ahmad]# kubectl get svc
NAME           TYPE        CLUSTER-IP     EXTERNAL-IP   PORT(S)          AGE
db-service     NodePort    10.96.39.143   <none>        6379:31861/TCP   23s
kubernetes     ClusterIP   10.96.0.1      <none>        443/TCP          41h
test-service   NodePort    10.96.168.17   <none>        8080:30609/TCP   31m
```

In the tester at `172.25.0.2:30609`, `db-service` on port `6379` returns **success**: within one namespace the short name works.

### Moving the database to a `dev` namespace

```console
[root@client1 ahmad]# kubectl create ns dev
namespace/dev created
```

Set `namespace: dev` in both files, then apply them:

```console
[root@client1 ahmad]# kubectl apply -f db-test-pod.yaml
pod/db-pod created
[root@client1 ahmad]# kubectl apply -f db-test-svc.yaml
service/db-service created
[root@client1 ahmad]# kubectl get po,svc -n dev
NAME         READY   STATUS    RESTARTS   AGE
pod/db-pod   1/1     Running   0          3m17s

NAME                 TYPE       CLUSTER-IP      EXTERNAL-IP   PORT(S)          AGE
service/db-service   NodePort   10.96.206.101   <none>        6379:30120/TCP   3m14s
```

Clean up the copies in `default`:

```console
[root@client1 ahmad]# kubectl delete po cloudops-pod db-pod
pod "cloudops-pod" deleted
pod "db-pod" deleted
[root@client1 ahmad]# kubectl delete svc db-service
service "db-service" deleted
```

```console
[root@client1 ahmad]# kubectl describe svc db-service -n dev
Name:                     db-service
Namespace:                dev
Selector:                 name=blue-55
Type:                     NodePort
IP:                       10.96.206.101
Port:                     <unset>  6379/TCP
TargetPort:               6379/TCP
NodePort:                 <unset>  30120/TCP
Endpoints:                10.244.1.12:6379
```

Now the test app (in `default`) **can't** reach the database by the short name `db-service`. It needs the **fully qualified DNS name**:

```
db-service.dev.svc.cluster.local   port 6379   → success
```

**Takeaway:** a short service name only resolves within its own namespace. Across namespaces, use `<service>.<namespace>.svc.cluster.local`. This shows namespace isolation and fully qualified service discovery.
