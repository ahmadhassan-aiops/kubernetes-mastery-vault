# 06. Deployments

**Deployment → ReplicaSet → Pods.** You describe the desired state in a config file; the Deployment creates a ReplicaSet, and the ReplicaSet manages the pods.

## Creating a Deployment

```yaml
# simple-deploy.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: simple-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: frontend
  template:
    metadata:
      labels:
        app: frontend
    spec:
      containers:
      - name: nginx
        image: nginx:1.14.2
        ports:
        - containerPort: 80
```

[root@client1 ahmad]# kubectl get deploy

## Self-Healing at Two Levels

**Delete a pod:** the ReplicaSet replaces it.

```console
[root@client1 ahmad]# kubectl delete po simple-deployment-c44bff498-dqfn6
pod "simple-deployment-c44bff498-dqfn6" deleted
[root@client1 ahmad]# kubectl get pods
NAME                                READY   STATUS    RESTARTS   AGE
simple-deployment-c44bff498-5mgln   1/1     Running   0          5s
simple-deployment-c44bff498-kc7hg   1/1     Running   0          6m23s
simple-deployment-c44bff498-pf2vc   1/1     Running   0          6m23s
```

The ReplicaSet shows it is **controlled by the Deployment** and logs the replacement pod:

```console
[root@client1 ahmad]# kubectl describe rs simple-deployment-c44bff498
Name:           simple-deployment-c44bff498
Selector:       app=frontend,pod-template-hash=c44bff498
Labels:         app=frontend
                pod-template-hash=c44bff498
Annotations:    deployment.kubernetes.io/desired-replicas: 3
                deployment.kubernetes.io/max-replicas: 4
                deployment.kubernetes.io/revision: 1
Controlled By:  Deployment/simple-deployment
Replicas:       3 current / 3 desired
Events:
  Normal  SuccessfulCreate  8m12s  replicaset-controller  Created pod: simple-deployment-c44bff498-pf2vc
  Normal  SuccessfulCreate  8m12s  replicaset-controller  Created pod: simple-deployment-c44bff498-kc7hg
  Normal  SuccessfulCreate  8m12s  replicaset-controller  Created pod: simple-deployment-c44bff498-dqfn6
  Normal  SuccessfulCreate  114s   replicaset-controller  Created pod: simple-deployment-c44bff498-5mgln
```

**Delete the ReplicaSet:** the Deployment recreates it straight away (note the `5s` age and `x2` in the events).

```console
[root@client1 ahmad]# kubectl delete rs simple-deployment-c44bff498
replicaset.apps "simple-deployment-c44bff498" deleted
[root@client1 ahmad]# kubectl get rs
NAME                          DESIRED   CURRENT   READY   AGE
simple-deployment-c44bff498   3         3         3       5s

[root@client1 ahmad]# kubectl describe deploy simple-deployment
...
Events:
  Normal  ScalingReplicaSet  76s (x2 over 11m)  deployment-controller  Scaled up replica set simple-deployment-c44bff498 from 0 to 3
```

## Experiment: Does a Deployment Adopt an Existing Pod?

Create a standalone pod with the label `app: frontend` first:

```yaml
# one-pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: cloudops
  labels:
    app: frontend
spec:
  containers:
  - name: nginx
    image: nginx:1.14.2
    ports:
    - containerPort: 80
```

Then apply the same Deployment with `replicas: 2`:

```console
[root@client1 ahmad]# kubectl apply -f one-pod.yaml
pod/cloudops created
[root@client1 ahmad]# kubectl apply -f simple-deploy.yaml
deployment.apps/simple-deployment created
[root@client1 ahmad]# kubectl get po,rs,deploy
NAME                                    READY   STATUS    RESTARTS   AGE
pod/cloudops                            1/1     Running   0          91s
pod/simple-deployment-c44bff498-c9x65   1/1     Running   0          2s
pod/simple-deployment-c44bff498-qxt4v   1/1     Running   0          2s

NAME                                          DESIRED   CURRENT   READY   AGE
replicaset.apps/simple-deployment-c44bff498   2         2         2       2s
```

**Result:** unlike the plain ReplicaSet experiment in [topic 05](05.%20ReplicationControllers%20and%20ReplicaSets.md), the Deployment ignored the existing pod and created 2 new ones.

**Reason: look at the labels.** A Deployment's ReplicaSet selects on `app=frontend` **plus** `pod-template-hash=c44bff498`. The standalone pod only has `app=frontend`, so it doesn't match:

```console
[root@client1 ahmad]# kubectl describe rs simple-deployment-c44bff498
Selector:       app=frontend,pod-template-hash=c44bff498
Labels:         app=frontend
                pod-template-hash=c44bff498
Controlled By:  Deployment/simple-deployment

[root@client1 ahmad]# kubectl describe po cloudops
Name:             cloudops
Namespace:        default
Service Account:  default
Node:             my-cluster-worker/172.25.0.3
Labels:           app=frontend
Status:           Running
IP:               10.244.1.27
QoS Class:        BestEffort
Events:
  Normal  Scheduled  10m   default-scheduler  Successfully assigned default/cloudops to my-cluster-worker
  Normal  Pulled     10m   kubelet            Container image "nginx:1.14.2" already present on machine
  Normal  Created    10m   kubelet            Created container: nginx
  Normal  Started    10m   kubelet            Started container nginx
```

Controllers only manage the pods they create, or unowned pods whose labels match their selector **exactly**.
