# 27. Network Policies

## What Are Network Policies?

Network Policies are rules that control **which pods may talk to which**. By default every pod can reach every other pod. Once a NetworkPolicy selects a pod, all traffic **not explicitly allowed** for that direction is blocked, like a firewall for pods.

| Direction | Meaning |
|---|---|
| **Ingress** | Incoming traffic: who can connect **to** the pod |
| **Egress** | Outgoing traffic: who the pod can connect **to** |

## A Classic Scenario: Frontend, Backend, Database

| Connection | Allowed? |
|---|---|
| Frontend → Backend | ✅ |
| Backend → Database | ✅ |
| Frontend → Database | ❌ |

Label the pods `role=frontend`, `role=backend` and `role=db`, then allow traffic into the database **only** from the backend:

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-backend-to-db
spec:
  podSelector:
    matchLabels:
      role: db
  ingress:
    - from:
        - podSelector:
            matchLabels:
              role: backend
```

The frontend doesn't match the rule, so it's blocked.

## The CNI Plugin Must Support It

Kubernetes doesn't enforce Network Policies itself; the **CNI plugin** does.

| Supports NetworkPolicy | Does not |
|---|---|
| **Calico** (most powerful and flexible), **Cilium**, **Weave**, **Kube-router** | **Flannel** (unless combined with Calico) |

> Test policies carefully: once a pod is selected, everything not explicitly allowed is denied.

```yaml

metadata:
  name: internal-service
  namespace: default
spec:
  ports:

    port: 8080
    protocol: TCP
    targetPort: 8080
  selector:
    name: internal
  type: NodePort
```

### Step 4: Only `internal` may reach `payroll`

```console
[ahmad@client1 ~]$ kubectl get netpol
No resources found in default namespace.
```

```yaml
# network-policy.yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: payroll-policy
  namespace: default
spec:
  podSelector:
    matchLabels:
      name: payroll
  ingress:
  - from:
    - podSelector:
        matchLabels:
          name: internal
    ports:
    - port: 8080
      protocol: TCP
```

```console
[ahmad@client1 ~]$ kubectl apply -f network-policy.yaml
networkpolicy.networking.k8s.io/payroll-policy created
[ahmad@client1 ~]$ kubectl get netpol
NAME             POD-SELECTOR   AGE
payroll-policy   name=payroll   6s
[ahmad@client1 ~]$ kubectl describe netpol payroll-policy
Name:         payroll-policy
Namespace:    default
Created on:   2025-05-20 00:39:27 +0500 PKT
Spec:
  PodSelector:     name=payroll
  Allowing ingress traffic:
    To Port: 8080/TCP
    From:
      PodSelector: name=internal
  Not affecting egress traffic
  Policy Types: Ingress
```

**Result:** payroll is now reachable **only from the internal pod**, not from external or the database, and not even through `nodeIP:nodePort`.

### Step 5: Only `payroll` may reach `external`

```yaml
# external-network-policy.yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: external-policy
  namespace: default
spec:
  podSelector:
    matchLabels:
      name: external
  policyTypes:
    - Ingress
  ingress:
    - from:
        - podSelector:
            matchLabels:
              name: payroll
      ports:
        - port: 8080
          protocol: TCP
```

```console
[ahmad@client1 ~]$ kubectl apply -f external-network-policy.yaml
networkpolicy.networking.k8s.io/external-policy created
[ahmad@client1 ~]$ kubectl get netpol
NAME              POD-SELECTOR    AGE
external-policy   name=external   6s
payroll-policy    name=payroll    17m
[ahmad@client1 ~]$ kubectl describe netpol external-policy
Spec:
  PodSelector:     name=external
  Allowing ingress traffic:
    To Port: 8080/TCP
    From:
      PodSelector: name=payroll
  Not affecting egress traffic
  Policy Types: Ingress
```

**Result:** the internal pod can **no longer reach** the external pod.

The same policies work on kind or kubeadm clusters, as long as the CNI supports them.
