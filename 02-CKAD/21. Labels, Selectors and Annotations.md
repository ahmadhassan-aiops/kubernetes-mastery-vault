# 21. Labels, Selectors and Annotations

| Concept | What it is | Used for |
|---|---|---|
| **Labels** | Key-value pairs attached to objects (`env: dev`, `tier: frontend`) | Grouping and selecting objects |
| **Selectors** | Queries that match labels (`--selector tier=frontend`) | Filtering in kubectl; linking Services, ReplicaSets and Deployments to pods |
| **Annotations** | Key-value metadata that is **not** used for selection | Build info, contact details, tool settings (such as `kubernetes.io/change-cause`) |

## Labelling a Pod

Generate a pod and replace the default `run: my-pod` label with your own:

```yaml
# my-pod.yaml
apiVersion: v1
kind: Pod
metadata:
  labels:
    env: dev
    tier: frontend
  name: my-pod
spec:
  containers:
  - image: nginx
    name: my-pod
    resources: {}
  dnsPolicy: ClusterFirst
  restartPolicy: Always
```

```console
[root@client1 ahmad]# kubectl apply -f my-pod.yaml
pod/my-pod created
```

## Selecting by Label

```console
[root@client1 ahmad]# kubectl get po --selector tier=frontend
NAME     READY   STATUS    RESTARTS   AGE
my-pod   1/1     Running   0          54s

[root@client1 ahmad]# kubectl get po --selector tier=frontend --no-headers
my-pod   1/1   Running   0     2m31s
[root@client1 ahmad]# kubectl get po --selector tier=frontend --no-headers | wc -l
1
```

`--no-headers | wc -l` is a handy way to **count** matching objects in the exam.

## Labels on Other Object Types

Add `tier: frontend` to a Service too:

```console
[root@client1 ahmad]# kubectl create service clusterip demo-svc --tcp=5678:8080 --dry-run=client -o yaml > demo-svc.yaml
[root@client1 ahmad]# vim demo-svc.yaml        # add the tier: frontend label
[root@client1 ahmad]# kubectl apply -f demo-svc.yaml
service/demo-svc created
[root@client1 ahmad]# cat demo-svc.yaml
apiVersion: v1
kind: Service
metadata:
  labels:
    tier: frontend
  name: demo-svc
spec:
  ports:
  - name: 5678-8080
    port: 5678
    protocol: TCP
    targetPort: 8080
  selector:
    app: demo-svc
  type: ClusterIP
```

`get all --selector` now finds both the pod and the Service:

```console
[root@client1 ahmad]# kubectl get all --selector tier=frontend --no-headers
pod/my-pod   1/1   Running   0     7m47s
service/demo-svc   ClusterIP   10.96.140.81   <none>   5678/TCP   88s
[root@client1 ahmad]# kubectl get all --selector tier=frontend --no-headers | wc -l
2
```

**Multiple labels** (comma = AND):

```console
[root@client1 ahmad]# kubectl get all --selector tier=frontend,env=dev --no-headers
pod/my-pod   1/1   Running   0     9m42s
```

Only the pod has both labels.

## Deployment Labels vs Pod Template Labels

A Deployment has **two places** for labels:

- `metadata.labels`: labels on the **Deployment** object itself
- `spec.template.metadata.labels`: labels given to the **pods** it creates

And `spec.selector.matchLabels` **must match the pod template labels**.

```yaml
# test-deploy (first attempt)
apiVersion: apps/v1
kind: Deployment
metadata:
  labels:
    tier: backend
    bu: finance
  name: test-deploy
spec:
  replicas: 3
  selector:
    matchLabels:
      app: test-deploy          # does not match the template below
  template:
    metadata:
      labels:
        env: prod
    spec:
      containers:
      - image: nginx
        name: nginx
```

```console
[root@client1 ahmad]# kubectl apply -f test-deploy
The Deployment "test-deploy" is invalid: spec.template.metadata.labels: Invalid value: map[string]string{"env":"prod"}: `selector` does not match template `labels`
```

Fix the selector so it matches:

```yaml
  selector:
    matchLabels:
      env: prod
```

```console
[root@client1 ahmad]# kubectl apply -f test-deploy
deployment.apps/test-deploy created
```

Now see which objects each label reaches:

```console
[root@client1 ahmad]# kubectl get all --selector tier=backend
NAME                          READY   UP-TO-DATE   AVAILABLE   AGE
deployment.apps/test-deploy   3/3     3            3           38s

[root@client1 ahmad]# kubectl get all --selector bu=finance,tier=backend
NAME                          READY   UP-TO-DATE   AVAILABLE   AGE
deployment.apps/test-deploy   3/3     3            3           116s
[root@client1 ahmad]# kubectl get all --selector bu=finance,tier=frontend
No resources found in default namespace.

[root@client1 ahmad]# kubectl get all --selector env=prod
NAME                               READY   STATUS    RESTARTS   AGE
pod/test-deploy-68578b5d96-db7c4   1/1     Running   0          2m38s
pod/test-deploy-68578b5d96-dj2l8   1/1     Running   0          2m38s
pod/test-deploy-68578b5d96-fjh56   1/1     Running   0          2m38s

NAME                                     DESIRED   CURRENT   READY   AGE
replicaset.apps/test-deploy-68578b5d96   3         3         3       2m38s
```

- `tier=backend` and `bu=finance` match only the **Deployment** (its own metadata).
- `env=prod` matches the **pods and the ReplicaSet** (they get the template labels).

```console
[root@client1 ahmad]# kubectl get all --selector env=prod --no-headers | wc -l
4
[root@client1 ahmad]# kubectl get rs --selector env=prod --no-headers | wc -l
1
```

## Handy Commands

```bash
kubectl get pods --show-labels            # show all labels
kubectl get pods -l env=dev               # -l is short for --selector
kubectl label pod my-pod env=prod --overwrite
kubectl annotate deploy test-deploy owner="ahmad"
```
