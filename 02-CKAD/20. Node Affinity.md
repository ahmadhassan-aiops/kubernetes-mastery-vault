# 20. Node Affinity

## Why Node Affinity? (The Limits of Node Selectors)

Node selectors only allow **exact key-value matches**, which makes them rigid. They can't say "prefer this node but don't require it", or handle several conditions. **Node affinity** supports richer expressions with operators (`In`, `NotIn`, `Exists`, `DoesNotExist`, `Gt`, `Lt`) and both **hard** and **soft** rules. It's defined under `affinity` in the pod spec.

## The Types of Node Affinity

### A. `requiredDuringSchedulingIgnoredDuringExecution` (hard)

If the rule isn't met, the pod is **not scheduled**. Once it's running, the rule is **ignored**, even if the node's labels change.

```yaml
affinity:
  nodeAffinity:
    requiredDuringSchedulingIgnoredDuringExecution:
      nodeSelectorTerms:
        - matchExpressions:
            - key: type
              operator: In
              values:
                - high-memory
```

### B. `preferredDuringSchedulingIgnoredDuringExecution` (soft)

Kubernetes **tries** to place the pod on matching nodes, but schedules it elsewhere if none are available. `weight` (1 to 100) ranks multiple preferences.

```yaml
affinity:
  nodeAffinity:
    preferredDuringSchedulingIgnoredDuringExecution:
      - weight: 1
        preference:
          matchExpressions:
            - key: zone
              operator: In
              values:
                - us-central1-a
```

### C. `requiredDuringSchedulingRequiredDuringExecution` (planned)

A **planned, not yet implemented** type that would enforce the rule for the pod's whole lifetime, evicting it if the node's labels stop matching.

### Step 2: Add a required affinity rule

```yaml
# my-deploy.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  labels:
    app: my-deploy
  name: my-deploy
spec:
  replicas: 6
  selector:
    matchLabels:
      app: my-deploy
  template:
    metadata:
      labels:
        app: my-deploy
    spec:
      containers:
      - image: nginx
        name: nginx
        resources: {}
      affinity:
        nodeAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
            nodeSelectorTerms:
            - matchExpressions:
              - key: platform
                operator: In
                values:
                - cloudops
```

## Affinity + Taints Together

Node affinity **attracts** pods to nodes; taints **repel** other pods. To dedicate nodes to one team or workload, use both: taint the nodes so other pods stay away, and give your pods a toleration **plus** node affinity so they go only there.
