# 15. Security Contexts

A `securityContext` controls **who** a container runs as and **what** it may do. It can be set at two levels:

| Level | Applies to | Can set |
|---|---|---|
| **Pod** (`spec.securityContext`) | All containers in the pod (defaults) | `runAsUser`, `runAsGroup`, `fsGroup`, ... |
| **Container** (`spec.containers[].securityContext`) | That container only | Everything above, plus **`capabilities`** |

- **Capabilities** (such as `NET_ADMIN` or `SYS_TIME`) add or drop specific Linux kernel privileges, and can **only** be set at container level. A common secure baseline is `drop: ["ALL"]`, then add back only what's needed.
- When both levels are set, pod-level fields act as **defaults** and **container-level settings win**.

## Test 1: No Security Context (Runs as Root)

```yaml
# test-pod1.yaml
apiVersion: v1
kind: Pod
metadata:
  name: test-pod
spec:
  containers:
  - name: ubuntu
    image: ubuntu
    command: ["sleep", "5000"]
```

```console
[root@client1 ahmad]# kubectl apply -f test-pod1.yaml
pod/test-pod created
[root@client1 ahmad]# kubectl exec test-pod -- whoami
root
[root@client1 ahmad]# kubectl exec test-pod -- pwd
/
```

## Test 2: Container-Level `runAsUser`

```yaml
# test-pod2.yaml
apiVersion: v1
kind: Pod
metadata:
  name: test-pod-2
spec:
  containers:
  - name: ubuntu-container
    image: ubuntu
    command: ["sleep", "5000"]
    securityContext:
      runAsUser: 1002
```

```console
[root@client1 ahmad]# kubectl apply -f test-pod2.yaml
pod/test-pod-2 created
[root@client1 ahmad]# kubectl exec test-pod-2 -- whoami
whoami: cannot find name for user ID 1002
command terminated with exit code 1
```

The process now runs as UID 1002. The image has no user with that ID, so `whoami` can't print a name, which proves it is **not root**.

## Test 3: Pod Level vs Container Level

```yaml
# 3-test-pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: test-pod-3
spec:
  securityContext:
    runAsUser: 1000
  containers:
  - name: ubuntu-container
    image: ubuntu
    command: ["sleep", "5000"]
    securityContext:
      runAsUser: 1008
```

```console
[root@client1 ahmad]# kubectl apply -f 3-test-pod.yaml
pod/test-pod-3 created
[root@client1 ahmad]# kubectl exec test-pod-3 -- whoami
whoami: cannot find name for user ID 1008
command terminated with exit code 1
```

**The container-level user (1008) wins** over the pod-level default (1000).

## Test 4: Two Containers, One Override

```yaml
# 4-test-pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: test-pod-4
spec:
  securityContext:
    runAsUser: 1000
  containers:
  - name: ubuntu-container
    image: ubuntu
    command: ["sleep", "5000"]
    securityContext:
      runAsUser: 1006

  - name: ubuntu-sidecar
    image: ubuntu
    command:
     - "sleep"
     - "4800"
```

```console
[root@client1 ahmad]# kubectl apply -f 4-test-pod.yaml
pod/test-pod-4 created
[root@client1 ahmad]# kubectl get po
NAME         READY   STATUS    RESTARTS   AGE
test-pod     1/1     Running   0          20m
test-pod-2   1/1     Running   0          14m
test-pod-3   1/1     Running   0          6m58s
test-pod-4   2/2     Running   0          6s

[root@client1 ahmad]# kubectl exec test-pod-4 -- whoami
Defaulted container "ubuntu-container" out of: ubuntu-container, ubuntu-sidecar
whoami: cannot find name for user ID 1006
command terminated with exit code 1

[root@client1 ahmad]# kubectl exec test-pod-4 -c ubuntu-container -- whoami
whoami: cannot find name for user ID 1006
command terminated with exit code 1
[root@client1 ahmad]# kubectl exec test-pod-4 -c ubuntu-sidecar -- whoami
ubuntu
```

- `ubuntu-container` uses its own override: UID **1006**.
- `ubuntu-sidecar` has no override, so it **inherits** the pod default UID 1000, which the Ubuntu image maps to the `ubuntu` user.

## Test 5: Adding a Capability

Capabilities go in the **container's** `securityContext`:

```yaml
# 5-test-pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: test-pod-4
spec:
  securityContext:
    runAsUser: 1000
  containers:
  - name: ubuntu-container
    image: ubuntu
    command: ["sleep", "5000"]
    securityContext:
      runAsUser: 1006
      capabilities:
        add: ["NET_ADMIN"]

  - name: ubuntu-sidecar
    image: ubuntu
    command:
     - "sleep"
     - "4800"
```

The shell prompt shows the difference between users:

```console
[root@client1 ahmad]# kubectl exec -it test-pod-4 -- bash
Defaulted container "ubuntu-container" out of: ubuntu-container, ubuntu-sidecar
I have no name!@test-pod-4:/$ exit
exit
[root@client1 ahmad]# kubectl exec -it test-pod -- bash
root@test-pod:/#
```
