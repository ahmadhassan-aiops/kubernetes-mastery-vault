# 05. ReplicationControllers and ReplicaSets

Both controllers keep a **fixed number of pod replicas** running.

## ReplicationController

```yaml
# rc.yaml
apiVersion: v1
kind: ReplicationController
metadata:
  name: myapp
  labels:
    app: frontend
spec:
  replicas: 5
  selector:
    app: frontend
  template:
    metadata:
      name: cloudops
      labels:
        app: frontend
    spec:
      containers:
      - name: alpha
        image: nginx
```

```console
[root@client1 ahmad]# kubectl apply -f rc.yaml

[root@client1 ahmad]# kubectl get replicationcontroller
```

### Self-healing test

Delete one pod and a replacement (`myapp-9p6t8`) appears within seconds:

```console
[root@client1 ahmad]# kubectl delete pods myapp-4zslp
pod "myapp-4zslp" deleted
[root@client1 ahmad]# kubectl get pods --watch
NAME          READY   STATUS    RESTARTS   AGE
myapp-9p6t8   1/1     Running   0          8s
myapp-cs82v   1/1     Running   0          12m
myapp-jmktm   1/1     Running   0          12m
myapp-w6rnw   1/1     Running   0          12m
myapp-xwrhd   1/1     Running   0          12m
```

Deleting the controller deletes its pods too:

```console
[root@client1 ahmad]# kubectl delete replicationcontroller myapp

[root@client1 ahmad]# kubectl get pods
No resources found in default namespace.
```

## ReplicaSet

```yaml
# replicaset.yaml
apiVersion: apps/v1
kind: ReplicaSet
metadata:
  name: myapp-replicaset
  labels:
    app: frontend-replicaset
    tier: development
spec:
  replicas: 5
  selector:
    matchLabels:
      app: myapp
  template:
    metadata:
      name: cloudops
      labels:
        app: myapp
    spec:
      containers:
      - name: alpha
        image: nginx
```

### Experiment: a pod that already matches the selector

First create a standalone pod carrying the label `app: myapp`:

```yaml
# single-pod.yaml
apiVersion: v1
kind: Pod
metadata:
  name: test-pod
  labels:
    app: myapp
spec:
  containers:
  - name: gama
    image: nginx
```

Then apply the ReplicaSet asking for 5 replicas:

```console
[root@client1 ahmad]# kubectl apply -f single-pod.yaml
pod/test-pod created
[root@client1 ahmad]# kubectl apply -f replicaset.yaml
replicaset.apps/myapp-replicaset created
[root@client1 ahmad]# kubectl get rs
NAME               DESIRED   CURRENT   READY   AGE
myapp-replicaset   5         5         5       13s

[root@client1 ahmad]# kubectl get pods
NAME                     READY   STATUS    RESTARTS   AGE
myapp-replicaset-585vw   1/1     Running   0          70s
myapp-replicaset-hb8bd   1/1     Running   0          70s
myapp-replicaset-qw4cb   1/1     Running   0          70s
myapp-replicaset-vqh5q   1/1     Running   0          70s
test-pod                 1/1     Running   0          81s
```

**Result: only 4 new pods were created.**

**Why?** Before creating pods, the ReplicaSet looks for existing pods that match its selector. `test-pod` had `app: myapp` and no owner, so the ReplicaSet **adopted** it as one of its 5 replicas and created only 4 more. This avoids running duplicate pods.

**Rules for adoption:**

- A ReplicaSet manages the pods it created, plus any pod with **matching labels and no `ownerReference`** (not already owned by another controller).
- A matching pod created **before** the ReplicaSet is adopted, so fewer new pods are created.
- If a matching orphan pod appears **after** the ReplicaSet already has its full count, the ReplicaSet adopts it and then deletes a surplus pod to stay at 5.

To have pods managed by a ReplicaSet, either let it create them, or create matching pods beforehand with no owner.

## ReplicationController vs ReplicaSet

| | ReplicationController | ReplicaSet |
|---|---|---|
| API | `v1` | `apps/v1` |
| Selectors | **Equality-based** only (`app=frontend`) | Equality-based **and set-based** (`matchLabels`, `matchExpressions` with `In`, `NotIn`, `Exists`) |
| Status | Older, legacy | Its successor |
| Managed by | Itself | Usually by a **Deployment** (rolling updates and rollbacks) |

In modern clusters, use **Deployments** (which manage ReplicaSets) rather than ReplicationControllers.
