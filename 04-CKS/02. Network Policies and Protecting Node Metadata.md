# 02. Network Policies and Protecting Node Metadata

By default, Kubernetes allows **all** traffic between pods, in and out. A **NetworkPolicy** acts as a firewall for pods: it can allow traffic based on **IP blocks (CIDR ranges), namespaces, pod labels and ports**, and grant a backend pod access from a specific namespace, IP range or pod, on specific ports and protocols.

> The basics of Network Policies, with a full payroll lab, are in [CKAD topic 27](../02-CKAD/27.%20Network%20Policies.md). This topic focuses on the **security** patterns.

## Prerequisites

- A cluster whose **CNI plugin enforces Network Policies** (Calico, Cilium). Flannel and kind's default `kindnet` don't.
- kubectl access with permission to create Network Policies.

### Calico on kind

Turn off kind's default CNI and install Calico:

```yaml
# kind-config.yaml
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
networking:
  disableDefaultCNI: true
  podSubnet: "192.168.0.0/16"
nodes:
- role: control-plane
```

```bash
kind create cluster --config kind-config.yaml
kubectl apply -f https://raw.githubusercontent.com/projectcalico/calico/v3.26.1/manifests/calico.yaml
```

## Best Practice: Deny All, Then Allow What's Needed

The first step to restrict a cluster is to **deny all incoming and outgoing traffic**, then allow only what is required.

### Step 1: Deny all ingress in a namespace

An empty `podSelector` (`{}`) selects **every pod**; an empty `ingress` list allows nothing.

```yaml
# deny-all-ingress.yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: deny-all-ingress
spec:
  podSelector: {}
  policyTypes:
  - Ingress
  ingress: []
```

```bash
kubectl apply -f deny-all-ingress.yaml
kubectl get networkpolicies
```

To block outgoing traffic too, add `Egress` to `policyTypes`.

### Step 2: Allow specific traffic

Allow only database pods to reach the web servers, on port 80:

```yaml
# allow-web-traffic.yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-web-traffic
spec:
  podSelector:
    matchLabels:
      app: webserver          # applies to pods labelled app=webserver
  policyTypes:
  - Ingress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: database       # only from pods labelled app=database
    ports:
    - port: 80                # only HTTP
```

## Building a Policy: The Checklist

1. **Name** the policy clearly and choose its namespace.
2. **Target pods:** `podSelector` decides which pods the policy protects. **Labels are required** to target pods.
3. **Type:** `Ingress`, `Egress` or both.
4. **Allowed sources or destinations:**
   - left empty, the policy **denies all** traffic of that type
   - `ipBlock` with a CIDR range, plus `except` for ranges to exclude
   - `namespaceSelector` for whole namespaces
   - `podSelector` for specific pods
5. **Ports and protocols.**

### AND vs OR in YAML

This is the most common mistake in Network Policies:

```yaml
# OR: two list items; traffic from EITHER source is allowed
ingress:
- from:
  - namespaceSelector:
      matchLabels:
        team: frontend
  - podSelector:
      matchLabels:
        role: api
```

```yaml
# AND: one list item; traffic must match BOTH selectors
ingress:
- from:
  - namespaceSelector:
      matchLabels:
        team: frontend
    podSelector:
      matchLabels:
        role: api
```

- **A new list item (`-`) means OR.**
- **Fields within the same item mean AND.**

## Protecting Node Metadata and Endpoints

Pods should not be able to reach sensitive endpoints on the node or the cloud platform.

1. **Enable node metadata concealment** where your platform offers it (some managed Kubernetes services do). It hides parts of the node metadata API from running pods, reducing what an attacker inside a pod can learn.
2. **Use Network Policies** to restrict which pods can talk to node resources and endpoints.

The most important endpoint is the **cloud metadata service** at `169.254.169.254`, which can hand out cloud credentials. Block it for all pods while still allowing other egress:

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: deny-cloud-metadata
spec:
  podSelector: {}
  policyTypes:
  - Egress
  egress:
  - to:
    - ipBlock:
        cidr: 0.0.0.0/0
        except:
        - 169.254.169.254/32
```

## Summary

- Labels are mandatory to target pods.
- A policy with no ingress or egress rules **denies all** traffic of that type.
- List items are **OR**; fields in one item are **AND**.
- Start with **deny all**, then add narrow allow rules.
