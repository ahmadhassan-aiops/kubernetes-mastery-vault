# 07. Restricting Access to the API Server

The **kube-apiserver** is the front door of the cluster: every user, controller and node talks to it. Securing it means controlling **who** can reach it and **what** they may do once they're in.

Every request passes three stages:

```text
request → 1. Authentication → 2. Authorization → 3. Admission control → etcd
              (who are you?)     (are you allowed?)   (is the object acceptable?)
```

## Ways to Restrict Access

| # | Control | What it does |
|---|---|---|
| 1 | **Network access to port 6443** | Firewalls, security groups or a private endpoint so only trusted networks reach the API server |
| 2 | **Authentication** | Client certificates, short-lived tokens, OIDC; disable anonymous access |
| 3 | **Authorization mode** | `--authorization-mode=Node,RBAC`; never `AlwaysAllow` |
| 4 | **RBAC** | Least-privilege Roles and bindings ([topic 08](08.%20RBAC%20with%20User%20Certificates.md)) |
| 5 | **Admission controllers** | Reject unsafe objects; `NodeRestriction` limits what each kubelet can modify |
| 6 | **Webhook authentication/authorization** | Delegate decisions to an external service |
| 7 | **Audit logging and monitoring** | Record who did what, and alert on suspicious access |

## Authentication Options

- **Client certificates:** the API server trusts certificates signed by the CA in `--client-ca-file`. Each user gets a key and a signed certificate (hands-on in topic 08).
- **Tokens:** short-lived ServiceAccount tokens from the TokenRequest API (`kubectl create token <sa>`), with an expiry and an audience.
- **OIDC:** users log in through an identity provider; best for teams.

## Demo: Why Exposure Matters

### An open proxy

`kubectl proxy` forwards requests to the API server **using your credentials**. Bound to every interface and accepting every host, it hands your admin access to anyone on the network:

```bash
kubectl proxy --address='0.0.0.0' --accept-hosts='^*$'   # dangerous: demo only
```

```bash
kubectl create namespace test
kubectl run web --image nginx -n test
```

From any browser that can reach the machine:

```text
http://<host>:8001/                               # every API path
http://<host>:8001/api/v1/namespaces/test/pods    # the pod list, no login
```

Keep `kubectl proxy` on its default `127.0.0.1` binding.

### Anonymous requests

Call the API server without any credentials:

```bash
curl -k https://192.168.56.10:6443
```

With anonymous authentication enabled, the request is accepted as user `system:anonymous`. RBAC usually denies it (`403 Forbidden`), but some paths such as `/version` or `/healthz` may still answer, and a single careless RoleBinding to `system:anonymous` or `system:unauthenticated` would expose much more.

## Hardening the API Server (kubeadm)

On kubeadm clusters, the API server is a **static pod**. Its flags live in a manifest on the control-plane node:

```bash
kubectl describe pod kube-apiserver-<control-plane-node> -n kube-system
# then, on the control-plane node:
cd /etc/kubernetes/manifests
ls -l
sudo cat kube-apiserver.yaml
```

Flags to check:

```yaml
spec:
  containers:
  - command:
    - kube-apiserver
    - --anonymous-auth=false                       # reject unauthenticated requests
    - --authorization-mode=Node,RBAC               # never AlwaysAllow
    - --enable-admission-plugins=NodeRestriction   # kubelets edit only their own node and pods
    - --client-ca-file=/etc/kubernetes/pki/ca.crt
    - --secure-port=6443                           # TLS port; the old insecure port 8080 is removed in current versions
    - --audit-log-path=/var/log/kubernetes/audit.log
    - --audit-policy-file=/etc/kubernetes/audit-policy.yaml
```

- **`--anonymous-auth`** defaults to `true` (enabled). Setting it to `false` rejects unauthenticated requests with `401 Unauthorized`. Note that kubeadm's own health probes rely on anonymous access to `/livez`, `/readyz` and `/healthz`; if you disable it, check that the static pod's probes still pass.
- The **kubelet watches the manifests folder**: saving the file restarts the API server automatically. Keep a backup copy *outside* `/etc/kubernetes/manifests` before editing.

After saving, wait for it to return and test again:

```bash
kubectl get pods -n kube-system | grep kube-apiserver
curl -k https://192.168.56.10:6443    # now 401 Unauthorized
```

## Other Good Habits

- Don't use default ServiceAccounts for workloads ([topic 09](09.%20Service%20Account%20Security.md)).
- Keep the cluster updated ([topic 10](10.%20Upgrading%20Kubernetes%20Frequently.md)).
- Review `kubectl config view` regularly and remove stale contexts and credentials.
