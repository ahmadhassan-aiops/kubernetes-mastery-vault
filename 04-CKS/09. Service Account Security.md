# 09. Service Account Security

Service accounts let applications in the cluster talk to the API server. Because their tokens are mounted into pods automatically, **anyone who gets a shell in a pod gets its token**. This topic shows the risk and how to reduce it.

> Service account basics are in [CKAD topic 16](../02-CKAD/16.%20Service%20Accounts%20and%20RBAC.md).

## The Problem: the Default Service Account

- Every namespace has a **`default`** service account.
- A pod that doesn't name a service account uses `default`, and its token is **mounted automatically** at `/var/run/secrets/kubernetes.io/serviceaccount`.
- Most applications never call the Kubernetes API, so that token is an unnecessary credential waiting to be stolen.

## Demo: Read the Token from Inside a Pod

```bash
kubectl create namespace dev
kubectl get serviceaccounts -n dev     # "default" already exists
kubectl run web --image nginx -n dev
kubectl get pod web -n dev -o yaml
```

We only gave a name, a namespace and an image, but the YAML shows defaults that were added for us:

```yaml
spec:
  serviceAccountName: default
  containers:
  - volumeMounts:
    - mountPath: /var/run/secrets/kubernetes.io/serviceaccount
      name: kube-api-access-xxxxx
      readOnly: true
```

Read it from inside the pod:

```bash
kubectl exec -it web -n dev -- sh
ls /var/run/secrets/kubernetes.io/serviceaccount
# ca.crt  namespace  token
cat /var/run/secrets/kubernetes.io/serviceaccount/token
exit
```

Anyone with this token can call the API server with the service account's permissions.

## The Fix, Step by Step

### 1. Create a dedicated service account with no token auto-mount

```bash
kubectl create serviceaccount test-svc -n dev --dry-run=client -o yaml > svc.yaml
```

Add the `automountServiceAccountToken` line:

```yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: test-svc
  namespace: dev
automountServiceAccountToken: false
```

```bash
kubectl apply -f svc.yaml
kubectl get serviceaccounts -n dev
```

### 2. Use it in a pod

```bash
kubectl run web2 --image nginx -n dev --dry-run=client -o yaml > web2.yaml
```

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: web2
  namespace: dev
spec:
  serviceAccountName: test-svc
  automountServiceAccountToken: false   # can also be set per pod; the pod setting wins
  containers:
  - name: web2
    image: nginx
```

```bash
kubectl apply -f web2.yaml
kubectl get pod web2 -n dev -o yaml | grep -A3 volumeMounts   # no serviceaccount mount
kubectl exec web2 -n dev -- ls /var/run/secrets/kubernetes.io/serviceaccount
# ls: cannot access ...: No such file or directory
```

### 3. Grant only what's needed (if the app does call the API)

```bash
kubectl create role test-role -n dev \
  --verb=get,list,watch,create \
  --resource=pods,deployments,services,configmaps

kubectl create rolebinding test-binding -n dev \
  --role=test-role \
  --serviceaccount=dev:test-svc

kubectl auth can-i list pods -n dev --as system:serviceaccount:dev:test-svc     # yes
kubectl auth can-i delete pods -n dev --as system:serviceaccount:dev:test-svc   # no
```

### 4. Turn off auto-mount on the default account too

```bash
kubectl patch serviceaccount default -n dev -p '{"automountServiceAccountToken": false}'
```

## Best Practices

- **One service account per application**; never share them, and don't use `default`.
- **`automountServiceAccountToken: false`** unless the app calls the API.
- **Least privilege** through Roles in the app's namespace; avoid `cluster-admin`.
- **Short-lived tokens:** since v1.24, Kubernetes no longer creates long-lived token Secrets automatically. Pods get projected tokens that expire and rotate; use `kubectl create token <sa>` for manual, time-limited tokens.
- **Review regularly:** remove unused accounts and bindings.
- Keep application secrets in **Secrets**, not in service account definitions.
