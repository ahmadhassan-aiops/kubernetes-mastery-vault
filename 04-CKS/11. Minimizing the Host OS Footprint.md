# 11. Minimizing the Host OS Footprint

Every package, service, open port and user account on a node is something an attacker can use. **Minimizing the host OS footprint** means removing everything a Kubernetes node doesn't need, so the attack surface is as small as possible.

The examples use Ubuntu (for instance on AWS EC2); RHEL equivalents are noted.

## The Hardening Checklist

1. Keep hosts updated
2. Remove unneeded packages and services
3. Limit user access to nodes
4. Harden SSH
5. Close unneeded ports and add firewall rules
6. Block unneeded kernel modules
7. Keep pods out of the host's namespaces and avoid privileged containers
8. Log and audit system activity

---

## 1. Update Regularly

```bash
sudo apt update && sudo apt upgrade -y        # RHEL: sudo dnf update -y
```

## 2. Remove Unneeded Packages and Services

```bash
dpkg -l                                       # installed packages (RHEL: rpm -qa)
sudo apt remove <package> -y
sudo apt autoremove -y

systemctl list-units --type service           # running services
systemctl list-unit-files --type service      # everything installed
sudo systemctl stop <service>
sudo systemctl disable <service>
```

Check running processes too: `ps aux` or `htop`.

When launching a node, start from a **minimal image** (Ubuntu Minimal, Bottlerocket, Flatcar, Talos) with as little preinstalled as possible.

## 3. Limit User Access to Nodes

Most users never need to log in to a node. Review the accounts and who can use `sudo`:

```bash
cat /etc/passwd                 # all accounts
sudo cat /etc/sudoers           # and /etc/sudoers.d/
sudo userdel -r <user>          # remove an unused account
sudo passwd -l <user>           # or lock it
```

Use a dedicated admin account with `sudo` rather than logging in as root.

## 4. Harden SSH

Nodes are usually reached through a **jump host**. Use SSH keys only:

```bash
cat /home/<user>/.ssh/authorized_keys   # check which keys can log in
```

In `/etc/ssh/sshd_config`:

```text
PermitRootLogin no
PasswordAuthentication no
```

```bash
sudo systemctl restart sshd
```

Restrict SSH to the jump host's IP with the firewall or a cloud security group.

## 5. Find and Close Open Ports

```bash
sudo netstat -tulnp                                  # or: sudo ss -tulnp
sudo netstat -tulnp | grep -i 9090 | grep -w -i listen

cat /etc/services | grep -i http                     # which service usually uses a port
sudo systemctl stop httpd && sudo systemctl disable httpd
```

Then allow only what the node needs (see [topic 12](12.%20Minimizing%20IAM%20Roles%20and%20External%20Network%20Access.md) for the firewall rules).

## 6. Block Unneeded Kernel Modules

A container can trigger the kernel to load a module (for example, by opening a socket of an unusual protocol). Block modules a node never needs, such as the `sctp` and `dccp` protocols:

```bash
lsmod                                  # loaded modules
```

```text
# /etc/modprobe.d/blacklist.conf
blacklist sctp
blacklist dccp
```

```bash
sudo shutdown -r now                   # reboot to apply
lsmod | grep -E 'sctp|dccp'            # nothing
```

`sudo rmmod <module>` unloads a module immediately, but only the blacklist survives a reboot.

## 7. Keep Pods Out of the Host

A pod that shares the host's namespaces or runs privileged can reach almost everything on the node. **Avoid this:**

```yaml
# DON'T: shares the host's IPC, network and process namespaces, and runs privileged
spec:
  hostIPC: true          # default false
  hostNetwork: true      # default false
  hostPID: true          # default false
  containers:
  - name: web
    image: nginx:latest
    securityContext:
      privileged: true   # default false: full access to the host's devices
```

Only system components such as CNI agents or node monitoring need this, and only with a clear reason. Ordinary workloads should run **unprivileged and as a non-root user** ([topic 15](15.%20Security%20Contexts%20for%20Least%20Privilege.md)).

Enforce it cluster-wide with **Pod Security Admission**: the `baseline` level already rejects `hostNetwork`, `hostPID`, `hostIPC`, `privileged` and `hostPath` volumes.

```bash
kubectl label namespace prod pod-security.kubernetes.io/enforce=baseline
```

(PodSecurityPolicy, which was used for this before, was removed in Kubernetes 1.25. Migration guide: https://kubernetes.io/docs/tasks/configure-pod-container/migrate-from-psp/)

## 8. Log and Audit

- `auditd` records system calls and file access on the host.
- `sysctl -a` shows kernel settings to review.
- Send logs off the node so an attacker can't erase them.
