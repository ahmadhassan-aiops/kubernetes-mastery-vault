# 14. Kernel Hardening with seccomp

## What Is seccomp?

Applications in user space make **system calls** to the kernel: `read`, `write`, `open`, `close`, `execve`, `accept`, `mount` and hundreds more. A compromised container that can call `mount`, `clock_adjtime` or `ptrace` can attack the host.

**seccomp** (secure computing mode) restricts **which system calls a container may make**. Like AppArmor ([topic 13](13.%20Kernel%20Hardening%20with%20AppArmor.md)), it's configured with **profiles**: here, lists of system calls to allow, deny or log.

### seccomp modes in the kernel

| Mode | Meaning |
|---|---|
| 0: disabled | No filtering |
| 1: strict | Only `read`, `write`, `exit` and `sigreturn` are allowed |
| 2: filter | A profile (BPF filter) decides per system call; this is what Kubernetes uses |

## Profiles

A profile has a **`defaultAction`** for any call not listed, and a list of **syscalls** with their own **action**:

| Action | Effect |
|---|---|
| `SCMP_ACT_ALLOW` | Allow the call |
| `SCMP_ACT_ERRNO` | Reject the call with an error |
| `SCMP_ACT_LOG` | Allow the call but log it |

The three example profiles from the Kubernetes docs:

**audit.json:** log every call (good for discovering what an app needs)

```json
{
  "defaultAction": "SCMP_ACT_LOG"
}
```

**violation.json:** reject every call (nothing will work)

```json
{
  "defaultAction": "SCMP_ACT_ERRNO"
}
```

**fine-grained.json:** reject everything except an explicit allow-list

```json
{
  "defaultAction": "SCMP_ACT_ERRNO",
  "architectures": ["SCMP_ARCH_X86_64", "SCMP_ARCH_X86", "SCMP_ARCH_X32"],
  "syscalls": [
    {
      "names": [
        "accept4", "epoll_wait", "pselect6", "futex", "madvise", "epoll_ctl",
        "getsockname", "setsockopt", "vfork", "mmap", "read", "write", "close",
        "arch_prctl", "sched_getaffinity", "munmap", "brk", "rt_sigaction",
        "rt_sigprocmask", "sigaltstack", "gettid", "clone", "bind", "socket",
        "openat", "readlinkat", "exit_group", "epoll_create1", "listen",
        "rt_sigreturn", "sched_yield", "clock_gettime", "connect", "dup2",
        "epoll_pwait", "execve", "exit", "fcntl", "getpid", "getuid", "ioctl",
        "mprotect", "nanosleep", "open", "poll", "recvfrom", "sendto",
        "set_tid_address", "setitimer", "writev"
      ],
      "action": "SCMP_ACT_ALLOW"
    }
  ]
}
```

### Where profiles live

The kubelet looks for `Localhost` profiles under its seccomp directory:

```text
/var/lib/kubelet/seccomp/<path given in localhostProfile>
```

### Profile types in a pod

| `type` | Meaning |
|---|---|
| `RuntimeDefault` | The container runtime's default profile; blocks dangerous calls and suits most apps |
| `Localhost` | A custom profile file on the node |
| `Unconfined` | No seccomp filtering |

By default, Kubernetes runs containers **Unconfined**. You can make `RuntimeDefault` the default for every pod with the kubelet setting `seccompDefault: true` in its config file (or the `--seccomp-default` flag). The feature is stable since v1.27, but the setting itself is still off unless you turn it on.

## The Workflow

1. Create the profile
2. Copy it to **every node** where the pod may run
3. Reference it in the pod's `securityContext`
4. Verify

## Lab (kubeadm cluster, node 192.168.56.10)

### Step 1: Put the profiles on the node

```bash
cat /var/lib/kubelet/config.yaml        # kubelet configuration
sudo mkdir -p /var/lib/kubelet/seccomp/profiles
cd /var/lib/kubelet/seccomp

sudo curl -L -o profiles/audit.json        https://k8s.io/examples/pods/security/seccomp/profiles/audit.json
sudo curl -L -o profiles/violation.json    https://k8s.io/examples/pods/security/seccomp/profiles/violation.json
sudo curl -L -o profiles/fine-grained.json https://k8s.io/examples/pods/security/seccomp/profiles/fine-grained.json
ls profiles
```

### Step 2: The audit pod

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: audit-pod
  labels:
    app: audit-pod
spec:
  securityContext:
    seccompProfile:
      type: Localhost
      localhostProfile: profiles/audit.json
  containers:
  - name: test-container
    image: hashicorp/http-echo:1.0
    args:
    - "-text=just made some syscalls!"
    securityContext:
      allowPrivilegeEscalation: false
```

> Set **`allowPrivilegeEscalation: false`** on every container: a pod can have several containers, and the setting is per container.

```bash
kubectl apply -f https://k8s.io/examples/pods/security/seccomp/ga/audit-pod.yaml
kubectl expose pod audit-pod --type NodePort --port 5678
kubectl get svc audit-pod                 # note the NodePort, e.g. 30040

curl http://192.168.56.10:30040/
# just made some syscalls!
```

In another terminal on the node, watch the system calls being logged:

```bash
sudo tail -f /var/log/syslog | grep audit-pod     # RHEL: /var/log/audit/audit.log or journalctl
```

Each request produces many log lines, one per system call. This is how you discover the calls an application needs.

```bash
kubectl delete service audit-pod --wait
kubectl delete pod audit-pod --wait --now
```

### Step 3: The violation pod

```bash
kubectl apply -f https://k8s.io/examples/pods/security/seccomp/ga/violation-pod.yaml
kubectl get pod violation-pod
# NAME            READY   STATUS             RESTARTS   AGE
# violation-pod   0/1     CrashLoopBackOff   1          6s

kubectl describe pod violation-pod      # Back-off restarting failed container
```

Every system call is rejected, so the container can't even start. Clean up:

```bash
kubectl delete pod violation-pod --wait --now
```

### Step 4: The fine-grained pod

```bash
kubectl apply -f https://k8s.io/examples/pods/security/seccomp/ga/fine-pod.yaml
kubectl get pod fine-pod                 # Running
kubectl expose pod fine-pod --type NodePort --port 5678
kubectl get svc fine-pod                 # e.g. 31994

curl http://192.168.56.10:31994/
# just made some syscalls!

sudo grep -i fine-pod /var/log/syslog    # nothing: allowed calls aren't logged
```

The app works because every call it needs is on the allow-list, and anything else would be rejected.

### Step 5: The everyday choice

For most workloads, simply use the runtime default:

```yaml
spec:
  securityContext:
    seccompProfile:
      type: RuntimeDefault
```

The `restricted` Pod Security Standard requires `RuntimeDefault` or `Localhost`.

Reference: https://kubernetes.io/docs/tutorials/security/seccomp/
