# 03. CIS Benchmark with kube-bench

## What Is the CIS Kubernetes Benchmark?

The **CIS (Center for Internet Security) Kubernetes Benchmark** is a set of security recommendations for hardening Kubernetes components: **etcd, the kubelet, kube-dns, the API server** and more. Its checks cover many levels of a cluster: pods, manifest files, policies, networking and so on.

The benchmark document is free to download (after registration) from the CIS website: https://www.cisecurity.org/benchmark/kubernetes

## kube-bench

**kube-bench** from Aqua Security runs the CIS checks automatically and reports which **pass** and which **fail**.

Repository: https://github.com/aquasecurity/kube-bench

### Install on RHEL/CentOS (my lab)

```bash
KUBE_BENCH_VERSION=0.10.1

curl -L https://github.com/aquasecurity/kube-bench/releases/download/v${KUBE_BENCH_VERSION}/kube-bench_${KUBE_BENCH_VERSION}_linux_amd64.rpm -o kube-bench_${KUBE_BENCH_VERSION}_linux_amd64.rpm

sudo yum install kube-bench_${KUBE_BENCH_VERSION}_linux_amd64.rpm -y
```

You can also download the binary for your architecture or run kube-bench as a container ([installation guide](https://github.com/aquasecurity/kube-bench/blob/main/docs/installation.md)).

### Run it

```bash
kube-bench
```

It checks every CIS criterion automatically and prints a report.

## Reading the Report

| Result | Meaning |
|---|---|
| **PASS** | The control is configured securely according to the benchmark |
| **FAIL** | The control is not configured securely; a risk was found |
| **WARN / SKIP** | Not applicable to this environment, or needs manual verification |

Each failed check comes with a **remediation**: the exact setting or command the benchmark recommends.

## The Hardening Loop

1. Run `kube-bench` and note the failed checks.
2. Look up each failed check in the CIS Benchmark (or kube-bench's remediation text) and apply the fix.
3. Run `kube-bench` again and confirm the failed checks now pass.
4. Repeat until every applicable check passes.

When all checks pass, your cluster is secured according to the CIS benchmark rules.

## Notes for Minikube

- Minikube is great for learning, but changing component configurations (etcd, kubelet, kube-dns, API server) inside it directly can break the cluster, so it's not recommended.
- Use kube-bench there to **understand** the findings, then apply the best practices through normal Kubernetes features and configuration rather than editing component configs by hand.
- kube-bench gives a **preliminary assessment**. It doesn't cover every aspect of security, so pair it with a manual review and the official hardening guidance, especially for production.
